## 摘要
求解组合优化问题不仅需要高效的算法，还需要精心设计的公式。尽管近期已有工作利用大语言模型自动化优化建模，但现有框架主要依赖严格的混合整数线性规划范式。本文认为，并非所有问题都最适合建模为MILP，因为将复杂领域强制转化为线性约束可能导致难以承受的建模复杂性，并严重限制求解器的灵活性。为此，我们提出OptiDSL，一个将焦点从严格的MILP公式转移到领域特定语言表示的框架。通过利用大语言模型将自然语言映射到标准化、领域公认的结构，OptiDSL将问题建模与执行解耦。该范式能够无缝集成多种专用求解器库，从传统启发式方法到现代基于学习的方法。在包含44种COP类型的综合基准上的实验结果表明，OptiDSL显著优于基于MILP的流程，建模准确率提升51.66%，建模时间减少91.71%。值得注意的是，在现有基准上它也优于基于MILP的流程，建模准确率提高23.09%。我们的代码可在 https://anonymous.4open.science/r/OptiDSL 获取。

## Abstract
Solving combinatorial optimization problems (COPs) requires not only efficient algorithms but also carefully crafted formulations. While recent works have leveraged LLMs to automate optimization modeling, current frameworks predominantly rely on a rigid mixed-integer linear programming (MILP) paradigm. In this paper, we argue that not all problems are best modeled as MILP, as forcing complex domains into linear constraints can induce prohibitive modeling complexity and severely restrict solver flexibility. To address this, we propose OptiDSL, a framework that shifts the focus from rigid MILP formulations to domain-specific language (DSL) representations. By utilizing LLMs to map natural language onto standardized, domain-accepted structures, OptiDSL decouples problem formulation from execution. This paradigm enables seamless integration with a diverse library of specialized solvers, ranging from traditional heuristics to modern learning-based methods. Experimental results on the comprehensive benchmark of 44 COP types show that OptiDSL significantly surpasses MILP-based pipelines, yielding a 51.66% gain in formulation accuracy and a 91.71% decrease in modeling time. Notably, it also outperforms MILP-based pipelines on the existing benchmark, achieving a 23.09% higher formulation accuracy. Our code is available at https://anonymous.4open.science/r/OptiDSL.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 组合优化问题（COPs）的求解不仅依赖高效算法，还依赖精心设计的数学公式化（formulation）过程。传统上这一过程由领域专家手工完成，耗时且易错。
- 近期工作利用大语言模型（LLMs）将自然语言问题描述自动转化为统一的 LP/MILP 公式，并通过 MILP 求解器求解。然而，该范式存在两大核心问题：
  1. **建模复杂性爆炸**：复杂组合约束（如车辆路径问题中的子回路消除）需要指数级数量的约束，超出 LLM 的上下文与推理能力，导致建模准确率显著下降。
  2. **求解器灵活性受限**：MILP 公式仅能对接 MILP 求解器，无法利用大量高效的领域专用算法（如启发式搜索、基于学习的神经组合优化方法等）。

**整体含义：**
- 论文提出核心论点：**并非所有优化问题都最适合建模为 MILP**。作者主张放弃以 MILP 为唯一中间表示的范式，转向基于领域特定语言（DSL）的建模范式，将"问题建模"与"求解执行"彻底解耦，从而实现更灵活、更准确的自动化优化建模。

## 2. 论文提出的方法论

### 2.1 核心思想
- 利用 DSL（即各领域公认的标准数据格式，如 VRP 领域的 VRPLIB 格式）作为自然语言问题描述与求解器之间的中间表示。
- DSL 是各领域求解器原生兼容的标准格式，可绕过 MILP 的数学复杂性，同时天然解锁多样化求解器池。

### 2.2 框架架构：OptiDSL

OptiDSL 包含三个核心组件：

**（1）DSL 任务规划（DSL-Based Task Formulation）**
- 建立了覆盖 5 大领域的 DSL 模板池：VRP（VRPLIB）、BPP、SP、KP（OR-Library）、GP（Network Repository）。
- 采用**分层 Agent 化工作流**：
  - **第一阶段：DSL 语义路由**——用简洁的元描述表示每个模板，LLM 作为路由代理，仅依据语义匹配将任务分发到最合适的单一模板 T\*，避免同时加载全部模板造成的上下文膨胀。
  - **第二阶段：DSL 实例化**——在选定模板的严格语法约束下，LLM 将自然语言文本结构化为正式的问题实例。除数据抽取外，还需进行逻辑推理，例如从"车辆无需返回起点"推断出 `OPEN_ROUTE: TRUE` 标志位。
- 该设计确保约束捕获的精确性，同时最小化 LLM 的上下文开销。基础模板可通过扩展适配新约束（如 CVRP 加时间窗变为 VRPTW）。

**（2）自适应求解器执行（Adaptive Solver Execution）**
- 构建了包含非学习类（Gurobi、LKH、PyVRP、OR-Tools、CP-SAT、遗传算法、动态规划、调度规则等）和学习类（RouteFinder、POMO、L2D、FJSP-DRL、DANIEL、MatNet、GOAL、PCT、FastT2T、DiffUCO 等）的多样化求解器池。
- 通过**离线经验画像**为每个 DSL 域的所有兼容求解器建立多维性能档案（最优间隙、计算时间等）；在线执行时，依据用户偏好（追求速度或追求最优性）动态路由到最优求解器，实现 Pareto 效率权衡。

**（3）基准评估（COPs Benchmark Evaluation）**
- 提出 OptiDSLBench 基准数据集，覆盖 44 种 COP 类型，每种 100 个实例，共 4400 个实例。
- 采用三阶段半自动数据生成流程：
  - **生成**：对每类 COP 初始化种子场景，再用 LLM 扩展新描述，限制不得重复标题确保语义多样性。
  - **检查与修正**：场景检查代理验证生成场景是否与正式 COP 定义逻辑一致，无效场景根据修改理由人工修订。
  - **数据占位符替换**：将结构生成与数据实例化解耦，用户定义占位符（如 ⟨demand⟩），LLM 负责识别与匹配，避免大规模数值生成错误。

### 2.3 关键公式/流程（文字描述）
工作流程为：自然语言问题描述 → DSL 语义路由 → DSL 实例化（生成结构化 DSL 数据文件） → 自适应求解器选择 → 求解执行 → 方案输出。与传统的"自然语言 → MILP 公式 → MILP 求解器"流程相比，OptiDSL 将中间表示从数学约束矩阵替换为标准化的领域数据文件，从根本上规避了约束爆炸问题。

## 6. 论文的主要结论与发现

1. **DSL 范式显著优于 MILP 范式**：在 OptiDSLBench 上，OptiDSL 相比最佳基线实现平均 ER 提升 10.13%、OR 提升 51.66%；VRP 领域增益最大（ER +13.05%，OR +68.83%）。

3. **跨领域泛化能力强**：在 5 个问题域上一致保持 ER>95%、OR>80%，而基线在 VRP 等复杂域上 OR 低至 11.79%。

## 7. 优点

- **范式创新**：明确论证了 MILP 并非唯一、也非最优的建模范式，提出以 DSL 为中心的替代路径，视角新颖且具有说服力（以 CVRP 的 MILP 约束爆炸为例）。
- **模块化设计**：两级流水线（路由 + 实例化）有效缓解上下文膨胀问题；建模与求解解耦使框架可无缝对接大量专用求解器。
- **工程实用性强**：自适应求解器选择机制基于离线画像和用户偏好，兼顾求解质量与计算效率，贴近真实工业部署需求。
- **基准构建严谨**：OptiDSLBench 采用半自动三阶段流水线（生成、检查、占位符替换），兼顾规模、多样性与数据准确性；平均参数 33.61，样本量 4400，超过现有同类数据集。
- **评估全面**：同时覆盖自建基准、现有 COP 基准、现有 MILP 基准三个层面，并进行了基础模型消融与求解器分析。
- **可复现性**：提供匿名代码链接；生成提示词与 DSL 模板等细节在附录中有充分展示。

## 8. 不足与局限

- **DSL 模板覆盖有限**：框架依赖预定义的 DSL 模板池，对于尚未形成标准 DSL 的新兴领域或跨领域混合问题，难以直接应用；模板扩展需要人工设计。
- **LLM 幻觉风险仍存**：尽管引入了场景检查代理，但生成阶段仍依赖 LLM 的输出质量；对占位符替换的依赖意味着用户必须预先定义好数据占位符，增加了使用门槛。
- **实验规模偏小**：主实验实例规模很小（VRP n=5，其他 n=10），虽然可扩展性实验到 n=50，但相对真实工业场景（数百甚至上千节点）仍有明显差距。
- **公平性存疑**：OptiDSL 与 CoE 均使用 DeepSeek-V3.2 这一强通用模型，而 ORLM/LLMOPT 使用较小的微调模型（Llama3、Qwen2.5-14B），存在模型能力不匹配导致的比较偏差；未在相同基础模型上比较各方法。
- **缺乏统计检验**：实验未报告多次运行的标准差、置信区间或显著性检验，难以判断结果的稳定性。
- **评估偏向 Gurobi**：统一用 Gurobi 作为求解器确保了建模公平性，但也意味着 DSL 结合专用求解器的完整优势还未在统一评估中被充分量化（有专门的求解器对比实验，但没有与基线端到端比较）。
