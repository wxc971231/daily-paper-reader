## 摘要
基于大型语言模型的自动启发式设计（LLM-AHD）在发现组合优化问题的有效启发式方面显示出巨大潜力。然而，现有方法主要优化单一启发式，而实际优化框架往往依赖多个相互作用的组件。直接扩展单启发式方法具有挑战性，因为早期组件选择可能忽视具有后期潜力的组件，而独立进化则忽略组件间的依赖关系。我们提出MuEvo，一个在集成级反馈下进化启发式集成的LLM驱动框架。MuEvo结合了动态组件管理（通过短预算探测和可逆生命周期在整个搜索过程中调整组件优先级）与LLM驱动的协同进化（通过多集成评估、跨组件信息共享、关系引导的对配对进化和自适应预算分配来协调组件种群）。我们在四个组合优化领域的选择超启发式和组件化蚁群优化上评估了MuEvo。结果表明，MuEvo持续改进人类设计的框架，并优于最先进的LLM-AHD方法的代表性多组件扩展，证明了其在控制器介导的启发式池和功能差异化算法组件上的有效性。

## Abstract
Large language model-based automated heuristic design (LLM-AHD) has shown strong potential in discovering effective heuristics for combinatorial optimization problems. However, existing methods primarily optimize a single heuristic, whereas practical optimization frameworks often rely on multiple interacting components. Directly extending single-heuristic methods is challenging because early component selection can overlook components with late potential, while independent evolution ignores inter-component dependencies. We propose MuEvo, an LLM-driven framework for evolving heuristic ensembles under ensemble-level feedback. MuEvo combines Dynamic Component Management, which uses short-budget probing and a reversible lifecycle to revise component priorities throughout the search, with LLM-Driven Co-Evolution, which coordinates component populations through Multi-Ensemble Evaluation, Cross-Component Information Sharing, Relation-Guided Pair Evolution, and Adaptive Budget Allocation. We evaluate MuEvo on selection hyper-heuristics and componentized ant colony optimization across four combinatorial optimization domains. Results show that MuEvo consistently improves human-designed frameworks and outperforms representative multi-component extensions of state-of-the-art LLM-AHD methods, demonstrating its effectiveness across both controller-mediated heuristic pools and functionally differentiated algorithmic components.

### 研究动机与背景

- **LLM-AHD 的兴起**：近年来，大型语言模型（LLM）被用于自动化启发式设计（Automated Heuristic Design, AHD），显著减少了对人类专家知识的依赖。代表方法包括 FunSearch、EoH（Evolution of Heuristics）、ReEvo（Reflective Evolution）、MCTS-AHD（蒙特卡洛树搜索辅助的启发式设计）等。
- **现有方法的根本局限**：绝大多数 LLM-AHD 方法只优化**单一启发式**（single heuristic），而实际组合优化问题的求解框架（如记忆算法、超启发式、蚁群优化等）往往依赖**多个功能各异、相互作用的启发式组件**——论文将这种共同协作的组件集合定义为"启发式集成"（Heuristic Ensemble）。
- **多启发式扩展的两大困难**：
  1. **早期选择不可逆（Late potential missed）**：固定预搜索（fixed pre-search）仅根据初始集成中的表现筛选组件，但组件的效用会随着协作组件的演进而改变，早期表现不佳的组件可能具有"后期潜力"，被过早丢弃。
  2. **独立进化忽略依赖（Inter-component dependencies ignored）**：多组件独立进化会忽视组件间的协同、冗余和冲突关系，单独改进的组件组合在一起未必构成好的集成。

## 二、论文提出的方法论

### 核心思想

MuEvo 将固定的一次性组件筛选和孤立优化，转化为**由集成级反馈驱动的动态共进化过程**，通过两大核心机制解决上述两个挑战：

1. **动态组件管理（Dynamic Component Management）**——解决"早期排除"问题
2. **LLM 驱动的协同进化（LLM-Driven Co-Evolution）**——解决"依赖被忽视"问题

### 关键技术细节

#### 1. 动态组件管理

- **短预算组件探测（Short-budget component probing）**：在固定其他组件的条件下，用相同的探测预算对每个有效组件进行短暂进化，计算探测分数：

  $$S_{probe}^{i} = f_i^{0} - f_i^{*}$$

  其中 f⁰ᵢ 是探测前集成适应度，f*ᵢ 是探测中观测到的最佳适应度。分数越大表示改进潜力越大（适应度越低越好）。

- **动态组件生命周期（Dynamic component lifecycle）**：依据探测分数对组件排序，将前 K<sub>A</sub> 个设为 Active，其余设为 Inactive。状态转换由集成级反馈驱动：
  - Active 组件若连续 τ_reject 次被 Multi-Ensemble Evaluation 拒绝，则被停用（deactivate），进入冷却期，且不能在选择或重新激活。
  - 当全局停滞达到 τ_stag 阈值、且距上次激活至少 τ_int 轮时，优先级最高的非冷却 Inactive 组件被晋升为 Active 并被强制选择一轮。
  - 接受替换会清除该组件的拒绝与冷却记录，并重置全局停滞计数。

#### 2. LLM 驱动的协同进化

将每个 LLH（低层启发式）视为一个子组件，维护其专属种群，种群内部采用 ReEvo 的反思引导进化机制。核心由四个机制构成：

- **多集成评估（Multi-Ensemble Evaluation）**：候选组件必须在三种代表性协作上下文中评估——当前最优集成（Best）、固定初始集成（Initial）、以及从存档中按质量和多样性选出的次级集成（Secondary）。改进量定义为：

  $$\Delta_i^k = f(\mathcal{E}^k) - f(\mathcal{E}^k[h_i \leftarrow h'_i])$$

  聚合得分：

  $$R_i = \sum_k w_k \Delta_i^k + \lambda_{min} \min_k \Delta_i^k - \lambda_{var} \operatorname{Std}(\{\Delta_i^k\})$$

  三项分别衡量加权改进、最差上下文表现和跨上下文一致性。接受条件：Δ_i^Best > 0 且 R_i > 0。联合进化的配对以相同方式整体评估，同时接受或拒绝。

- **跨组件信息共享（Cross-Component Information Sharing）**：在优化目标组件前，总结当前各组件的功能角色与依赖关系，结合关系记忆（relation memory）中存储的每种配对关系推断、接受/拒绝替换时对应的协作组件版本、历史上下文相关增益等，构建目标特定的关系上下文，引导 LLM 对 hᵢ 进行改进。

- **关系引导的配对进化（Relation-Guided Pair Evolution）**：每 q 轮进化，对组件对进行打分——结合当前实现的结构依赖与关系记忆中的经验交互证据，选出最高分组件对作为一个联合候选，整体生成、整体评估、整体接受或拒绝。

- **自适应预算分配（Adaptive Budget Allocation）**：为每个有资格的组件打分：

  $$P_i = w_I I_i + w_V eV_i + w_S \min\left(\frac{z_i}{H_z}, 1\right) + w_R er_i - w_\rho \rho_i$$

  其中 Iᵢ 为近期改进率（基于验证的种群适应度），eVᵢ 为归一化适应度方差，erᵢ 为最近 H<sub>r</sub> 次被选中后的归一化集成替换奖励，zᵢ 为距上次接受替换的连续选中次数，ρᵢ 为该组件已获得的正规进化轮次比例。各分量分别捕捉近期进展、种群多样性、暂时停滞、集成级奖励和分配频率。

### 算法流程（伪代码概述）

```
输入：框架 F、初始集成 E₀、探测预算 B_probe、进化预算 B_evo
1. 用短预算探测所有有效组件，获得探测分数
2. 依据探测分数初始化 Active/Inactive 状态
3. 进入进化主循环：
   a. 选择目标组件或配对（由自适应预算分配或关系引导配对进化决定）
   b. 构建关系上下文
   c. 通过反思引导的交叉与变异生成候选

   e. 根据接受规则决定是否替换全局集成
   f. 更新组件生命周期、关系记忆、分配统计与存档
4. 返回最优集成 E*
```

1. **MuEvo 在 SHH 框架上全面优于基线**：在全部 16 个数据集上改进人工设计的 LLH 集成，在 14 个数据集取得最低或并列最低的平均差距。例如将 TSP-L 的最强基线差距从 6.261% 降至 5.237%，Flowshop VRF100 从 3.506% 降至 3.236%。
2. **MuEvo 在 ACO 框架上同样有效**：在 8 个数据集中的 7 个取得最低差距（如 TSP-M 从 26.65% 降至 6.956%）。
3. **无固定进化模式持续最优**：Batch 在部分数据集最强、Split 在其他数据集最强、Single 在 CVRP 上较强——但没有哪种固定模式在所有场景下稳定。MuEvo 在所有场景中表现最一致。
4. **跨控制器泛化良好**：用 ADAPHH 进化出的 LLH 集成直接迁移到 HAHA、NAHH、VNSTW 均带来显著改进（TSP-VNSTW 从 7.04% 降至 3.44%），表明未过拟合训练控制器。
5. **消融验证了所有核心机制的重要性**：移除任一机制都会导致性能下降，其中动态组件管理在 TSP-ACO 上的影响最大（5.855% → 13.86%），跨组件信息共享和配对进化在 BPP-SHH 上影响最大。
6. **对不同 LLM 骨干鲁棒**：三种 LLM 均大幅超越原始启发式，最优模型因框架而异。

## 七、优点

1. **问题定义清晰、动机充分**：系统性提出"多启发式 LLM-AHD"问题，给出形式化定义，并指出多启发式目标函数不可分的本质困难。用具体观测案例（h′₈ 符号反转）为问题动机提供实证支撑。
2. **方法设计新颖且系统**：将"动态组件管理"（解决早期排除问题）与"LLM 驱动协同进化"（解决依赖问题）有机结合，而非简单地将单启发式方法并行化。四种协同进化机制各司其职、闭合反馈。
3. **多集成评估设计精巧**：在固定评估预算下同时检查三种协作上下文，兼顾了加权改进、最差情况鲁棒性和跨上下文一致性，有效避免了单上下文评估的偶然性。
4. **工程化设计的细致考量**：LLM 兼容的 SHH 框架改造（统一调用接口、已验证操作封装、领域算法库）显著降低了 LLM 生成代码的幻觉和错误率；ACO 框架采用"受信任领域内核"与可替换组件分离的设计原则，保障求解器可行性。
5. **实验验证全面**：跨两个结构不同框架、四个 COP 领域、多数据集、多控制器、多 LLM 骨干，覆盖主实验、消融、泛化测试，证据链完整。
6. **对基线公平**：为基线设计了三种模式（Single/Split/Batch），Split 模式甚至获得三倍预算仍不敌 MuEvo，增强了结论的可信度。
7. **代码透明度高**：附录详细给出了提示词模板、组件接口、超参数配置、实例列表和演化的启发式代码示例，有助于复现。

## 八、不足与局限

1. **算力/资源报告缺失**：未报告 GPU 使用情况、API 调用总量、运行时长等关键资源信息，复现成本难以评估。
2. **缺乏超参数敏感性分析**：生命周期阈值（τ_reject、τ_stag、L_cool）、上下文权重（wI、wV、wS 等）、配对间隔 q 等均固定，未报告这些参数对性能的影响，难以判断方法对超参数的敏感性。
3. **额外预算的公平性问题**：MuEvo 使用 25×N 的探测预算（N 为组件数），虽然明确申明不计入主预算，但基线方法只有各自的预搜索预算；总计算量并未严格对齐，对公平性有一定影响。
4. **仅覆盖两类多组件框架**：SHH（同级交互）和 ACO（流水线交互）虽然是代表性场景，但其他类型的多启发式框架（如多目标优化、超参数-算法联合优化等）未验证。
5. **LLM 成本与随机性**：仅使用 3 个随机种子、3 种 LLM 后端，统计显著性检验（如 t 检验、Wilcoxon 检验）未报告。
6. **领域覆盖有限**：尽管覆盖 4 个 COP 领域，但都是经典组合优化问题（TSP、CVRP、BPP、Flowshop），未扩展到更复杂的现实问题（如 MILP、SAT、Job Shop 等）。
7. **没有分析失败案例**：MuEvo 在个别数据集（如 TSP-SS 的最优性差距 0.651%）不如某些基线最优结果，但论文未深入分析为何在这些场景下提升有限。
8. **未讨论 LLM 输出质量对方法的影响**：虽然提及格式修复和预检修复机制，但未量化报告 LLM 生成代码的有效率/修复率等指标，无法评估 LLM 不确定性对方法的实际影响。
