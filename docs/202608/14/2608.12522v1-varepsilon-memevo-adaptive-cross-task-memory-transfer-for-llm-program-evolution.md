## 摘要
基于LLM的程序进化系统（如FunSearch和AlphaEvolve）已展现出发现新颖算法的强大能力，但通常独立优化每个任务，在完成后丢弃搜索经验。我们提出了$\varepsilon$-MemEvo，一个用于LLM程序进化中的跨任务知识迁移的框架。$\varepsilon$-MemEvo将先验经验存储为任务无关的策略记忆：即成功算法策略的紧凑自然语言摘要，而非原始代码，从而支持在不同API和评估器的任务间进行迁移。为避免语义不匹配记忆带来的负迁移，$\varepsilon$-MemEvo使用自适应注入门控，决定是否应注入检索到的记忆以及注入强度。我们在涵盖数学优化和系统工程领域的8个多样化优化基准上评估了$\varepsilon$-MemEvo，采用内容级留一法协议，排除目标任务的记忆条目。在主要GPT-5骨干模型上，$\varepsilon$-MemEvo在所有8个任务上相较于AdaEvolve提升了AUCC，平均相对增益为+8.7%，并将早期收敛平均提升了+9.4%。消融研究表明，朴素的记忆注入可能灾难性失败，而自适应门控在所有五个消融任务中保持安全。数据更新的后验在观测状态下是可解释的：它在搜索改进时倾向于跳过，并跨越早期和晚期平台期从跳过转向提示。这些增益产生的计算开销不到1%。

## Abstract
LLM-based program evolution systems such as FunSearch and AlphaEvolve have shown strong ability to discover novel algorithms, but typically optimize each task in isolation, discarding search experience after completion. We introduce $\varepsilon$-MemEvo, a framework for cross-task knowledge transfer in LLM program evolution. $\varepsilon$-MemEvo stores prior experience as task-agnostic tactic memories: compact natural-language summaries of successful algorithmic strategies rather than raw code, enabling transfer across tasks with different APIs and evaluators. To avoid negative transfer from semantically mismatched memories, $\varepsilon$-MemEvo uses an adaptive injection gate that decides whether retrieved memories should be injected, and at what intensity. We evaluate $\varepsilon$-MemEvo on 8 diverse optimization benchmarks spanning mathematical optimization and systems engineering, using a content-level Leave-One-Out protocol that excludes target-task memory entries. On the primary GPT-5 backbone, $\varepsilon$-MemEvo improves AUCC over AdaEvolve on all 8 tasks, with a mean relative gain of +8.7%, and improves early-stage convergence by +9.4% on average. Ablations show that naive memory injection can fail catastrophically, while adaptive gating remains safe across all five ablation tasks. The data-updated posterior is interpretable in observed states: it favors skip during improving search and shifts from skip to hint across early and late plateaus. These gains incur less than 1% computational overhead.

## 2. 论文提出的方法论

- **核心思想**：在基础进化框架（AdaEvolve）之上增加两个跨任务模块：
  1. **Tactic Memory Bank（战术记忆库）**：存储从已完成任务的成功程序中提取的、任务无关的自然语言策略摘要（而非原始代码），从而支持不同 API 与评估器之间的迁移。
  2. **Adaptive Injection Gate（自适应注入门控）**：根据搜索状态动态决定注入记忆的行为（skip/hint/guide），核心目标是避免负迁移。
- **关键技术细节**：
  - **策略提取**：任务完成后，用 GPT-4.1-mini 从最终最优程序中提取通用算法描述（如“两阶段优化：贪心初始化+梯度下降”），生成一条战术记忆条目（含策略、类型标签、任务描述、嵌入向量）。
  - **语义检索**：用 text-embedding-3-small 对当前任务描述编码，与记忆库条目计算余弦相似度，并用得分加权排序（见公式 2），返回 top-3 策略。
  - **状态空间**：由搜索相位（improving / plateau / stagnating，基于全局改进率 ρ）和任务阶段（early / late，t/M<0.4 为 early）组合成 6 个离散状态。
  - **动作空间**：三个注入强度：
    - *skip*：不注入记忆，使用基础提示；
    - *hint*：仅将策略作为可选参考；
    - *guide*：将 top-1 策略作为推荐方法并注入到范式突破生成中。
  - **Thompson Sampling 门控**：每个 (state, action) 对维护 Beta 分布。初始设置 informative priors：`(improving, skip) ~ Beta(3,1)`、`(stagnating, guide) ~ Beta(3,1)`，其余为 Beta(1,1)。每轮采样后选择后验均值最高的动作。
  - **延迟奖励机制**：窗口 w=5 轮后判断当前动作是否使最佳分数超过注入前的分数（ε=1e-8），成功则更新 α，否则更新 β。使用 FIFO 队列处理并发未决记录，任务结束时清算。
  - **LOO 协议**：评估任务 k 时，记忆库排除任务 k 自身的条目，只使用其他任务的记忆；但策略 π 的完整后验保留（因为它是任务无关的状态-动作映射）。
- **算法流程**（Algorithm 1）：每轮迭代 → 计算状态 → 采样各动作的 θ → 选择最大 θ 对应动作 → 若非 skip 则检索 top-3 策略 → 构建增强提示 → LLM 生成新程序 → 评估并更新种群 → 记录动作和前置分数 → 延迟更新 Beta 后验。

## 8. 不足与局限

- **实验规模有限**：任务数量仅 8 个，领域覆盖虽广但每个领域任务少；消融仅 5 个任务，统计功效有限。
- **未提供方差信息**：仅给均值，没有误差棒/置信区间（除 bootstrap 外），难以判断任务间方差。
- **记忆库扩展性未知**：论文未测试超过 8 条记忆时的检索精度、门控校准和负迁移频率变化，也没有层次化记忆机制（作者将之列为未来工作）。
- **基座框架依赖**：ε-MemEvo 只能增强底层进化框架，无法弥补基础搜索的缺陷；跨任务记忆不能替代良好的探索机制。
- **规则基线遗漏**：未与“stagnation 触发 + k-strike 自动禁用”的更强规则基线比较；作者承认这可能恢复到大部分安全性，但需要任务相关阈值。
- **理论保证有限**：虽然引用了 TS 的 regret 界，但仅说明“不匹配时 guide 拉取次数 O(log T)”，对整体方法的收敛性没有形式化保证。
- **潜在偏差**：
  - 记忆提取使用 GPT-4.1-mini，可能引入模型自身的偏差或信息损失；
  - 检索相似度权重公式中的常数（0.3、0.01）和顶部选择 k=3 是手工设定，未做敏感性分析；
  - 不同任务难度差异大（如 PRISM 接近饱和），可能使部分指标对比不明显。
- **应用限制**：方法面向可重复评估的程序进化任务，不适用于无明确评分函数或评价噪声过高的场景。

## 总结

ε-MemEvo 是首个将跨任务记忆迁移形式化为自适应干预问题的 LLM 程序进化框架，通过“战术记忆库 + 自适应门控”的组合，在 8 个优化基准上稳定提升收敛性能并避免负迁移，为多任务进化算法研究提供了有价值的范式和证据。但其验证范围、可扩展性和与更强规则基线的比较仍有待完善。
