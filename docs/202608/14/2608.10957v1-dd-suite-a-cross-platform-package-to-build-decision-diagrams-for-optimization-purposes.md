## 摘要
决策图（DDs）已成为离散优化中的强大工具，支持从割生成过程、分解方法到专门的 branch-and-bound 搜索等广泛算法。尽管有这种增长，它们的应用仍然有限，部分原因是大多数现有的 DD 代码专门针对特定算法或应用，因此难以重用。我们介绍了 DD-suite，一个用于构建和操作离散优化 DDs 的跨平台、开源软件包。DD-suite 通过共享建模接口同时提供 Python 和 C++ 版本，并允许用户为任何以递归形式表达的离散优化问题构造精确、限制和松弛的 DDs。该软件包实现了 DD 约简过程、获取原始界和对偶界的最短路径例程、可视化工具以及广泛的自动化测试套件。此外，它还包括详细的文档、一个支持网页和四个组合问题的即用示例。DD-suite 并非一个封闭的求解器，而是设计为可扩展的构建模块：用户可以在生成的图之上添加新的构造机制或运行自定义算法，正如我们在一个嵌入最先进的混合整数规划求解器中的基于 DD 的割平面过程所展示的那样。我们的数值实验表明，C++ 实现比 Python 实现快 5-6 倍，同时产生完全相同的图，并且与专门的 Rust 框架 ddo 相比仅保持在一个小的常数因子范围内，这确认了 DD-suite 将易访问、可扩展的代码库与有竞争力的性能相结合。

## Abstract
Decision diagrams (DDs) have become a powerful tool for discrete optimization, supporting a wide range of algorithms that span cut-generation procedures, decomposition methods, and specialized branch-and-bound searches. Despite this growth, their adoption remains limited, partly because most existing DD code is tailored to a specific algorithm or application and is therefore hard to reuse. We introduce DD-suite, a cross-platform, open-source software package for building and manipulating DDs for discrete optimization. DD-suite is available in both Python and C++ through a shared modeling interface, and lets users construct exact, restricted, and relaxed DDs for any discrete optimization problem expressed in recursive form. The package implements the DD reduction procedure, shortest-path routines for obtaining primal and dual bounds, a visualization tool, and an extensive automated test suite. Furthermore, it includes extensive documentation, a support webpage, and ready-to-use examples for four combinatorial problems. Rather than a closed solver, DD-suite is designed as an extensible building block: users can add new construction mechanisms or run custom algorithms on top of the resulting diagram, as we illustrate with a DD-based cutting plane procedure embedded in a state-of-the-art mixed-integer programming solver. Our numerical experiments show that the C++ implementation is 5-6 times faster than the Python one while producing identical diagrams, and remains within a small constant factor of ddo, a specialized Rust framework, confirming that DD-suite combines an accessible, extensible codebase with competitive performance.

为解决上述问题，论文提出了 **DD-suite**：一个跨平台（Python 和 C++）、开源的DD构建与操作软件库，以**可扩展的构建模块**为定位，而非封闭求解器。其核心目标是降低DD研究的入门门槛，使研究者能够专注于自定义算法的开发，而无需重复实现底层DD基础设施。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心设计思想

- **递归模型作为问题描述语言**：用户通过继承 `AbstractProblem` 抽象类，实现递归形式的动态规划（DP）模型（状态、转移函数、可行赋值集合），DD-suite自动完成后续DD构建。
- **分离可行性集合与目标函数**：DD仅编码可行解集合（状态和可行赋值），奖励函数/目标函数在优化时才传入。这一设计使同一个DD可以重复用于不同目标函数的优化，特别适用于切割平面等需要反复查询DD的场景。
- **门面模式（Facade）架构**：`DD` 类作为统一门面协调各模块（DD数据结构、构建器、图算法、切割生成器），模块间高度解耦，便于独立扩展。
- **统一的自顶向下构建模板**：所有构建器继承自 `AbstractDDBuilder`，共享同一个层间构建流程（算法1），仅在"层构建后处理"和"构建结束后处理"两个扩展点上有所差异。

### 2.2 关键技术细节

**问题描述接口**：用户需实现以下核心函数：
- `transition_function()`：描述状态转移并判定赋值可行性
- `get_priority_for_discard_node()`：限制DD的节点丢弃启发式
- `get_priority_for_merge_nodes()` 和 `merge_operator()`：松弛DD的节点合并启发式与合并算子

**三种DD类型**：
- **精确DD（Exact）**：完整表示所有可行解，通过最长路径获得最优解
- **限制DD（Restricted）**：当层宽度超过上限W时丢弃低优先级节点，产生可行解子集，提供原始界（primal bound）
- **松弛DD（Relaxed）**：当层宽度超过W时合并高优先级节点，可能引入不可行路径，提供对偶界（dual bound）

**合并算子的有效性条件**（Hooker的形式化）：合并状态需满足三个条件——① 可行赋值集合包含原状态的并集；② 即时奖励不小于原状态；③ 转移函数保持松弛关系。

### 2.3 核心算法流程

**算法1：DD自顶向下构建**
1. 创建根节点（初始状态）和终节点（虚拟状态）
2. 逐层遍历，对每个节点为每个可行赋值创建弧
3. 利用转移函数确定子节点状态，**确保不创建重复状态节点**
4. 当层节点数超过最大宽度W时，执行合并（松弛DD）或丢弃（限制DD）
5. 最后一层所有弧指向终节点

**算法2：分组式合并（grouping-based merge）**
- 按合并优先级排序节点
- 从容差δ=0开始，合并优先级差距不超过δ的连续节点组
- 若层仍超宽，增加δ（跳到下一个最小优先级间隙），重复合并
- 相比默认的两两合并，一次可合并多个节点，在宽层上更高效

### 2.4 其他功能

- **约简过程**：从终层开始自底向上合并同构子图，获得最紧凑的精确DD
- **最短/最长路径**：基于贝尔曼-福特算法，利用DD的分层有向无环图结构加速，用于获取界
- **可视化**：导出GML格式文件，支持yEd软件查看
- **测试套件**：Python版230+测试、C++版260+测试

## 7. 优点：方法或实验设计上的亮点

1. **高可扩展性的架构设计**：模块化、门面模式、统一构建模板（AbstractDDBuilder的两个扩展点），使得新增构建机制只需覆盖一个方法，新增算法只需实现接口即可，无需改动底层代码。
2. **双语言一致接口**：Python和C++版本具有相同的文件名、类名和函数名，降低语言迁移成本；Python适合原型开发、C++适合性能要求场景。
3. **可行性集合与目标函数分离**：同一DD可复用于不同目标函数的重复优化，契合Benders分解、列生成、切割平面等高级算法场景。
4. **完备的软件工程实践**：Clean Code原则、完整的文档字符串、230+（Python）和260+（C++）自动测试、GML导出可视化、支持网页和教程。
5. **三层验证体系**：跨语言一致性（20,880配置）、与Gurobi的外部验证（282实例）、界有效性验证（17,589配置），证明实现正确性。
6. **以实证展示扩展性**：通过分组式松弛机制和切割平面两个具体示例，而非仅口头宣称扩展性，有说服力。
7. **性能透明有据**：与ddo的差距用具体结构差异解释（入弧/出弧的权衡），而非掩盖系统开销。

1. **性能上非最优**：C++实现比ddo慢约2倍（论文定位为"小的常数因子"），对于追求极致性能的场景，DD-suite不是最佳选择；数据结构的通用性换来了速度折损。

2. **切割平面实验覆盖有限**：
   - 仅在一个基准（SOC-K，90实例）上验证切割平面效果，未扩展至其他问题类型
   - 仅在根节点调用切割（通过用户回调），未实现分支过程中的按需切割
   - 表3中C++和Python各变体的实例数存在差异（如JointFlowCuts的#Solv不同），论文解释为求解器内部时序差异，但未提供统计显著性检验

3. **对用户实现质量依赖度高**：
   - 松弛合并算子需满足Hooker三个条件，但DD-suite不自动校验
   - 丢弃/合并启发式的质量完全依赖用户实现，缺省启发的效果未做系统评估
   - transition_function()的实现效率直接影响构建时间，论文建议用户优化但未给出指导方法

4. **功能展望中提到的方向尚未实现**：如零压缩DD（ZDD）、基于分离的迭代精化构建、列消除算法等，论文仅在结论中列出为未来工作。

5. **实验对比对象有限**：
   - 未与CODD（C++ DD求解器）和Haddock（DD编译框架）做数值对比
   - 未与GPU加速方案（[52]的工作）对比
   - 与ddo的对比仅在构建时间层面，未对比整体B&B求解性能（因为DD-suite定位不同）

6. **自生成实例集的可泛化性**：集合覆盖实例采用特定的带状结构生成方案，虽然利于DD构建，但与真实应用中可能出现的一般集合覆盖结构可能存在偏差。
