## 摘要
大邻域搜索通常随机选择决策变量的子集进行迭代优化。为了高效求解不同问题，研究者倾向于结合不同领域的结构特征来设计变量选择策略。本文构建了一个对MiniZinc格式下所有问题均通用的自动化流水线。通过向LLM提供我们的语义指南，我们引导LLM生成一个图生成器，该生成器将任意问题类型的实例映射为统一加权图，其中节点表示决策变量，边表示约束关系。这些与问题无关的图指导我们的基于结构的局部改进框架（SLIM）进行变量选择。同时，加权图使得所有问题实例能够共享相同的通用图表示，从中可以提取相同的图特征并用于配置选择。我们在20个MiniZinc竞赛问题的实例上评估了我们的流水线，发现与一次性Gurobi基线相比，算法选择达到了39.5%的平均问题加权胜率，是最优单一配置（19.3%）的两倍多。配置和特征消融进一步将性能提升至44.0%，表明基于LLM的语义生成能够为约束优化实现有效的自动结构提取和特征提取。

## Abstract
Large neighborhood search normally selects a random subset of decision variables for iterative optimization. For efficiently solving different problems, researchers tend to design variable selection strategies by taking into account structural features from different domains. In this paper, we build an automatic pipeline that is problem-agnostic to all problems in the MiniZinc format. By prompting an LLM with our semantic guidelines, we guide the LLM to produce a graph generator that maps any instance of a problem type to a uniform weighted graph, where nodes represent decision variables and edges represent constraint relationships. These problem-agnostic graphs guide our structure-based local improvement framework (SLIM) in variable selection. Meanwhile, the weighted graph enables all problem instances to share the same generic graph representation, from which the same graph features can be extracted and used for configuration selection. We evaluated our pipeline on instances across 20 MiniZinc competition problems, finding that algorithm selection achieves a 39.5% average problem-weighted win rate against a one-shot Gurobi baseline, more than doubling the best single configuration (19.3%). Configuration and feature ablation boost the performance further to 44.0%, demonstrating that LLM-based semantic generation enables effective automated structure extraction and feature extraction for constraint optimization.

## 2. 论文提出的方法论

**核心思想：**

利用LLM作为"语义编译器"（semantic compiler），将MiniZinc约束模型转化为确定性、可审计的Python程序（图生成器），该程序将任意问题实例映射为统一的加权图。SLIM框架与算法选择器均在该统一图表示上运行，实现对不同问题的通用化处理。

**流水线结构（两个阶段）：**

**① 问题特定阶段（每个问题类型只需执行一次）：**

- 将MiniZinc模型（.mzn）与人工设定的语义权重指南交给LLM（Claude Opus 4.5）。
- LLM生成一个Python程序——图生成器（generator.py），该程序能解析特定问题的实例并构造加权图。
- 每个问题的图生成器合成通常在几分钟内完成。

**② 问题无关阶段（每个实例执行）：**

- **变量提取器**：解析MiniZinc实例，提取决策变量、定义域及数组索引，生成variables.json。
- **图生成器**：根据variables.json构建加权图。
- **SLIM框架**：在加权图上进行变量选择与局部优化。
- **特征提取与算法选择器**：从图中提取通用特征，选择最优SLIM配置。

**统一图表示（Problem-Agnostic Graph Format）：**

- **节点**：表示决策变量，带两个属性：
  - 权重 w∈[0,1]：变量对目标函数的重要性
  - 定义域大小 d∈N：变量可能的取值数量
- **边**：表示变量之间的约束关系，边权 w∈[0,1] 反映耦合强度

**生成指南（Semantic Guidelines）：**

1. **目标相关分量权重较高**（≥0.6）：因为它们直接影响最终目标值，容易被提取算法选中。
2. **大型全局约束使用低权重**：如 alldifferent 约束规模 n>10 时使用权重 max(0.1, 1/n)，防止团主导（clique domination）；小型约束（n≤5）保持强耦合（≥0.8）。
3. **避免孤立节点**：确保所有节点都有被提取和优化的可能性。
4. **权重有界**：多个约束连接同一对变量时，按 W=1−∏ᵢ(1−wᵢ) 聚合，保证权重不超1。

**SLIM框架的提取方法：**

- **BFS提取**：按节点权重随机选择起始节点，沿按边权排序的边扩展，能同时捕获变量的重要性（节点权重）与原始问题约束结构（边连接）。
- **LNS提取**：按节点权重随机收集变量，但不考虑局部性偏好（不要求连通性）。
- 两种提取方式均在达到预算 b 时停止；预算由基于定义域大小的指标限定。
- 另有**冻结模式**：用于收集要冻结（不优化）的变量，与提取模式互补。

**配置空间：**

共30种SLIM配置，包括：
- 局部预算 b ∈ {10, 20, 50, 70, 100, 200}
- 每轮超时 t ∈ {20, 30, 45, 60} 秒
- 不同提取策略（BFS/LNS）与冻结模式组合

**算法选择（Algorithm Selection）：**

- 从统一加权图中提取**54个通用特征**（拓扑统计、节点/边权重分布、定义域大小统计与相关性、变量元数据、实例数值参数等）。
- 训练**多输出随机森林回归**模型，预测每种配置相对一次性Gurobi基线的改进幅度（improvement margins），选择预测最优的配置。
- 训练时使用问题加权样本权重，防止实例数多的类型（如RCPSP占38%）主导训练。
- 共实现5种选择方法：回归、集成、二分类、多分类、两阶段——仅在训练损失目标与预测内容上有差异。

## 6. 论文的主要结论与发现

1. **LLM能有效生成图生成器**：通过语义指南提示LLM，可自动为不同MiniZinc问题生成有效的图生成器，无需领域专家参与，每个问题的生成仅需数分钟。

4. **消融进一步提升**：配置与特征消融后，平均问题加权胜率进一步提升至44.0%。
5. **统一图表示是关键使能器**：统一加权图表示使得跨20个异构问题的特征提取与算法选择成为可能，无需针对每个问题设计专门的算法选择器。

## 7. 优点

1. **真正的问题无关性**：管道从图生成、变量选择到算法配置选择均不依赖问题类型，适用于任何MiniZinc格式的问题，打破了以往SLIM方法必须领域定制的限制。
2. **LLM作为一次性离线编译器**：LLM只在生成图生成器时使用一次，运行阶段完全依靠确定性Python程序，结果可审计、可复现，避免了运行时LLM的不确定性。
3. **语义引导的图构造**：通过精心设计的语义指南（权重范围、大约束降权、权重聚合公式等），LLM生成的图在语义层面反映了原始问题的结构信息，而非仅提取语法关系。
4. **统一图表示带来的跨问题算法选择**：这是论文最具创新性的亮点——同一54维特征集可应用于20个异构问题，实现了跨问题组合选择，这是传统领域特定算法选择方法无法做到的。
5. **实验验证扎实**：20个问题、多种子、消融实验、问题加权评估等多维度验证，提供了充分的证据链。
6. **资源开放**：提供了Zenodo仓库用于复现实验结果，增强了研究的可重复性。

## 8. 不足与局限

1. **LLM生成图的近似性**：图生成器虽然是LLM根据语义指南生成的并经过验证，但本质上仍是LLM对真实约束语义的近似（approximation），可能导致某些问题上的结构信息不够准确——这也是论文指出的SLIM在rectangle-packing和VRP上表现不佳的可能原因。
2. **基准覆盖面有限**：评估仅覆盖MiniZinc竞赛实例，该基准以约束规划为主，对Gurobi天然适合的整数规划类型覆盖有限；未验证在更广泛的优化问题（如非线性优化）上的适用性。
3. **依赖Gurobi作为子求解器**：SLIM的局部优化完全依赖Gurobi处理子问题，限制了流水线在Gurobi不支持的问题类型上的应用。
4. **未与其他LNS方法对比**：仅对比了Gurobi基线和各种SLIM配置之间，未与现有的随机LNS、自适应LNS或神经LNS方法进行对比，无法评估相对已有元启发式方法的优势。
5. **算法选择方法较为基础**：仅使用随机森林回归等简单方法，未与AutoFolio、SUNNY等成熟算法选择工具对比，"任何更先进的算法选择方法都会进一步提升效果"的说法缺乏实证。
6. **静态权重**：图中的权重来自LLM的语义分析，是静态的，不随搜索过程的推进动态更新；论文提到未来可使用禁忌搜索或自适应调整来避免重复优化，说明当前方法对此尚未覆盖。
7. **计算开销大**：SLIM每个实例需60分钟总预算且由30种配置分别运行，实验总计算量巨大，可能限制该方法在实践中的广泛部署。
8. **数据不平衡**：尽管使用问题加权缓解了RCPSP等大问题对评估的主导，但训练集中各问题实例数差异仍然极大，小样本问题上的选择器可靠性存疑。
