## 摘要
基于大型语言模型（LLM）的自动化算法设计通常将算法作为完整、不可分割的程序进行进化。虽然这种整体程序视角简化了搜索空间，但它从根本上将有用的局部逻辑与其宿主程序耦合在一起。因此，当整个程序被丢弃时，有价值的代码片段也随之消失，使得评估单个算法组件的贡献变得极其困难。为解决这一问题，我们提出了原始感知代码进化（PACE），通过将局部逻辑表示为称为可执行算法原语（EAPs）的持久单元，将其与完整程序解耦。为了实现代码级迁移，PACE维护一个动态的EAP集合。算法进化由原始感知算子驱动，这些算子在结构上保证这些组件的保留和跨程序迁移。为了有效评估它们，PACE利用基于父代相对性能改进的汤普森采样，指导从集合中选择原语，而无需额外的评估数据集。在四个任务上的实验表明，PACE能够有效发现具有竞争力的算法，同时在结构上保留有价值的算法组件。

## Abstract
Large Language Model (LLM)-based automated algorithm design typically evolves algorithms as complete, indivisible programs. While this whole-program perspective simplifies the search space, it fundamentally couples the useful local logic to its host program. Consequently, valuable code snippets vanish when the overall program is discarded, making it highly difficult to assess the contribution of individual algorithmic components.To address this, we propose Primitive-Aware Code Evolution (PACE), which decouples local logic from complete programs by representing it as persistent units called Executable Algorithmic Primitives (EAPs). To enable code-level transfer, PACE maintains a dynamic set of EAPs. Algorithm evolution is driven by primitive-aware operators that structurally guarantee the retention and cross-program transfer of these components. To evaluate them effectively, PACE leverages Thompson sampling based on parent-relative performance improvements, guiding primitive selection from the set without requiring extra evaluation datasets. Experiments on four tasks demonstrate that PACE effectively discovers competitive algorithms while structurally preserving valuable algorithmic components.

## 方法论

### 核心思想

- 将算法视为由可调用函数（EAP）组成的组合体。EAP 具有稳定的文本描述 `σe` 和可执行实现 `ϕe`，一旦进入动态集合 `E_t`，就独立于宿主程序持久存在（`e ∈ E_t ⇒ e ∈ E_{t+1}`）。
- 完整算法仍由评估器 `J` 打分；EAP 没有独立目标，只通过“父代相对改进”积累迁移证据，影响后续被选择和暴露的概率。

### 关键技术细节

1. **EAP 表示与调用集**：`e = (σe, ϕe)`，算法 A 的 EAP 调用集为 `C(A; E_t) = {e ∈ E_t | A invokes e}`。EAP 实现一旦确定便不再修改，修改实现即定义新 EAP。
   
2. **四个原始感知算子**（每个算子都限定子代 EAP 调用集的结构约束，并使用 AST 验证器强制检查）：
   - **P1 插入（Primitive Insertion）**：父代保留原有 EAP，并插入一个由 Thompson 采样选出的新 EAP（`C_V(A') = C_V(A) ∪ {e+}`），该次父子比较产生关于 `e+` 的一次聚焦迁移观测。
   - **P2 替换（Primitive Replacement）**：移除父代中后验均值最低的被调用 EAP，并插入一个 Thompson 采样选出的新 EAP，聚焦信用分配给新注入的 EAP。
   - **P3 保留精化（Primitive-Preserving Refinement）**：不改变 EAP 集合成员，只允许 LLM 优化调用顺序、参数、阈值或交互方式；不触发后验更新。
   - **P4 原始感知交叉（Primitive-Aware Crossover）**：从两个父代选出 EAP 并集，要求子代至少从每个父代各继承一个 EAP，在最大容量 `k` 内自由重组；因多个原语同时变更加剧信用混淆，不触发后验更新。

3. **自适应 EAP 选择与 Thompson 采样**：
   - 将一次“聚焦迁移试验”定义为固定父代 A、注入 EAP e、生成子代 A′，奖励为 `r_e = I[J(A′) > J(A)]`。
   - 对每个 EAP 维护 Beta 后验 `Beta(αe, βe)`，初始为 `Beta(1,1)`，按 `(αe, βe) ← (αe + r_e, βe + 1 − r_e)` 更新；子代分数下降、平局或运行错误时增加 `βe`，LLM 未能结构集成该 EAP 则试验无效、不更新。
   - 选择时从每个可用 EAP 的后验中采样 `θe ∼ Beta(αe, βe)`，选最大者；新 EAP 先经历短期的强制预热曝光，避免因观测不足而饿死。

4. **EAP 发现机制**（每代至多提出 1 个，且两种机制互斥，提取优先）：
   - **EAP 生成**：在任务描述和当前 top-k EAP 实现的条件下，让 LLM 生成功能上不同的新 EAP，避免冗余。
   - **EAP 提取**：从新产生的历史最优完整算法中，将复杂内部计算重构为独立 EAP，不改变也不重新评估源程序；后续聚焦试验会检验其真实可迁移性。

5. **完整流程**（Algorithm 1）：
   初始化种群和 EAP 集 → 循环选择父代与操作符 → 若为插入/替换则用 Thompson 采样确定焦点 EAP → LLM 生成子代 → 用 AST 验证器检查调用集约束，不合格则修复（最多 3 次尝试）→ 评估子代、更新种群 → 若操作符有焦点 EAP 则按父代相对性能更新其后验 → 每代结束时提出至多一个 EAP（提取或生成）→ 返回搜索历史中的最优算法。

## 主要结论与发现

- PACE 在四个任务上均优于现有 LLM 类 AAD 基线，且在某些任务上超过神经基线（如 Racing Car 零样本测试 98.90，超过 PPO 的 85.688）。
- 在 Bipedal Walker 上，现有 AAD 方法普遍严重失败（多个基线得分接近零甚至为负），而 PACE 测试得分 133.71，显著优于 MLES cold-start（15.42）。
- TSP-Construct 上 PACE 在所有规模（n=50/200/500/1000）均最优；TSP-ACO 上 in-domain 与最优基线接近（5.795 vs 5.774），但 out-domain 迁移性能全面领先，尤其在 n=1000 时明显优于 MCTS-AHD 等基线。

- 将更强 LLM 仅用于 EAP 发现阶段即可显著提升整体性能，验证了“EAP 独立表示”能让我们用极小额外成本换取不成比例的收益。
- 将算法演化解耦为持久原语的演化，既提升了搜索质量，又结构性地保留了有价值组件，为 AAD 提供了一种组件级组合的新范式。

## 优点

- **问题切入精准**：直指全程序进化范式中“有用局部逻辑随整体淘汰而丢失”的关键弱点，并给出可操作的 EAP 抽象。

- **资源开销低**：无需额外评估数据集或额外评估预算，EAP 发现用 token 极少（约 1.6%），性价比高。

## 不足与局限

- **独立原语假设**：方法假设 EAP 可被单独评估和选择，但复杂算法中不同原语间可能存在强耦合，独立评估无法完全反映联合交互（作者自己也在局限性中承认）。
- **实验方差与统计验证**：部分结果标准差很大（如 Bipedal Walker 训练 67.06±72.63），且未报告显著性检验，可能削弱结论的统计学可靠性。
- **基线覆盖不全**：未在实验部分直接对比同为“结构复用”思路的最新方法（如 EoH-S、EvoLattice、BEAM、G-LNS），仅在相关工作提及，削弱了对“组件复用路线”优势的直接证明。
- **LLM 生成依赖**：算子依赖 LLM 在结构约束下生成有效子代，虽然设置了修复机制，但若 LLM 能力不足，仍可能频繁产生非法调用集，影响搜索效率。
- **计算资源报告模糊**：只提到 CPU 环境，未说明 LLM API 调用的时间开销、EAP 验证与修复的额外耗时，可复现性方面有待补充。
- **参数 k 的扩展性**：k 同时限制每个算法的 EAP 数量与结构尝试次数，该耦合可能不利于不同任务的自适应调整。
