## 摘要
我们探究大型语言模型（LLM）能否为定义明确的运筹学（OR）问题设计有效算法。我们研究了库存控制、排队网络控制和商品组合优化。我们评估了两种级别的LLM使用：在级别1中，模型接收一个具体问题实例并返回针对该实例的解决方案；在级别2中，模型仅接收问题类别描述和广泛的参数范围，并返回一个将实例参数映射到解决方案的算法。人工输入极少：我们提供一个未经调优的问题描述提示，模型可访问具有固定计算预算的Python沙盒工具。我们测试的最强模型gpt-5.6-sol在几乎所有评估实例上匹配或优于现有最佳方法。即使在级别2（返回的算法在见到评估实例前就已固定）也是如此。性能在相隔不到八个月发布的模型之间也显著提升，表明这一能力正在快速进步。因此，对于我们研究的定义明确的运筹问题，单次未经调优的LLM查询即可生成能与专门方法竞争的算法。这些结果表明，前沿LLM可以成为定义明确的运筹问题中算法设计的严肃实证基线。

## Abstract
We ask whether large language models (LLMs) can design effective algorithms for well-specified operations research (OR) problems. We study inventory control, queueing network control, and assortment optimization. We evaluate two levels of LLM use: at level 1, the model receives one problem instance and returns a solution for that instance; at level 2, it receives only the problem class description and broad parameter ranges, and returns an algorithm that maps instance parameters to solutions. Human input is minimal: we give one untuned prompt that describes the problem, and the model has access to a Python sandbox tool with a fixed compute budget.   The strongest model we test, gpt-5.6-sol, matches or outperforms the best existing method on almost all evaluated instances. This holds even at level 2, where the returned algorithm is fixed before seeing the evaluation instances. Performance also improves sharply across models released less than eight months apart, suggesting that this capability is moving quickly. Thus, for the well-specified operations problems we study, a single untuned LLM query can already produce algorithms competitive with specialized methods. These results suggest that frontier LLMs can be a serious empirical baseline for algorithm design in well-specified OR problems.

## 2. 方法论
- **问题形式化**：定义问题类别 \(C=(\Theta, X, R)\)，实例为参数 \(\theta\in\Theta\)，可行解集为 \(X(\theta)\)，奖励函数为 \(R(\theta, x)\)。实例可以是单次决策（如品种集合）或序贯决策（如库存/排队的策略）。
- **两种 LLM 调用级别**：
  - **Level 1**：LLM 给定一个具体实例，返回该实例的解决方案。
  - **Level 2**：LLM 仅给定问题类别描述和参数范围，返回一个可复用算法 \(\sigma\)，该算法之后被运行时把任意实例参数映射为解。Level 2 更接近“算法设计”的常规含义。
- **交互协议**：
  - 使用单一未调优提示词，不指定求解思路、不命名基准方法。
  - LLM 可调用 Python 沙箱（标准库 + numpy + scipy，无 Gurobi 等外部求解器），有固定计算预算（默认 3600 秒，最多 50 次调用；品种优化 Level 1 为 900 秒）。
  - 返回的代码不得调用 LLM；Level 2 的算法在评估时需在 30 秒内生成每个实例的解（软约束）。
- **评估方式**：将 LLM 的结果与“每个实例上现有最佳方法”比较（包括精确最优解、调优启发式或强化学习策略）；LLM 结果不进入比较器。
- **模型**：gpt-5.6-sol、gpt-5.4、gpt-5.1（OpenAI）和 claude-fable-5（Anthropic），发布时间跨度不足八个月。

- **训练数据污染无法排除**：这些 OR 问题及公开 benchmark 实例很可能出现在预训练数据中，模型可能通过记忆而非真正推理生成算法。论文对这一点进行了讨论，但未提供强有力的反证（如构造全新问题族）。

## 9. 总结与个人评价

本文是一个设计严谨、执行规范的实证研究。它用一套极简的协议——一段未调优的自然语言提示、一个受限的 Python 沙箱、逐实例最佳比较——回答了“LLM 能否充当运筹学算法设计者”这一既前沿又实际的问题。最强模型在大多数类别上达到甚至超过了现有最优方法，且生成的是可读、可复用的策略代码，这确实是令人印象深刻的结果。

但我也认为，结论应被谨慎解读。实验规模（尤其是库存与排队）仍偏小，稳定性和污染控制仍未完全解决；LLM 的胜利更像是在“给定数学定义 + 给定反馈预算”下的快速原型能力，而不是对问题深层结构的理论性突破。它生成的结构（如 capped base-stock、压力型调度）大多是对已有思想的重新组合，而非真正意义上的新算法范式。

总体而言，这篇论文最大的贡献在于：为“LLM 作为算法设计器”建立了一个可复现、可比较的评估框架，并提供了扎实的第一手数据。对 OR 和 ML 社区而言，它值得作为一个严肃的经验基线和未来工作的起点。
