## 摘要
基于仿真的优化（SBO）在随机动态下评估可执行策略，但大多数方法将仿真器视为黑箱：聚合得分对候选策略进行排名，却没有揭示它们为何失败或应更改哪些策略逻辑。我们提出了一种LLM引导的启发式设计框架，该框架利用重复仿真进行选择，并利用事件级轨迹进行诊断。每个当前策略通过多次重复进行评估，同时重放其得分最低的一次运行，以生成可查询的轨迹。一个管理智能体根据这些证据制定瓶颈假设，而编辑智能体则并行实施代码级修订。在执行检查和重复评估后，目前最佳的选择仅保留改进项。LLM修订发生在评估批次之间，而每个仿真运行由固定策略控制。我们在动态生产与自动导引车（AGV）调度的离散事件仿真中评估该框架。在使用Gemini-3.1-Pro进行的五次独立优化运行中，最终平均分数在仿真器的0-100分制上平均为77.51分。在得分最高的运行中，基于轨迹的诊断促使了主动充电、距离感知的AGV分配以及重新平衡的调度优先级，将目前最佳平均分数从62.49提高到78.61。在100个匹配的随机种子上，最佳最终策略在每个种子上都优于具有代表性的滚动MILP、基于规则和元启发式策略，并且在无需重新优化的情况下，在随机故障下保持了其优势。在为更长的时域和可变的订单到达间隔进行单独重新优化后，所得策略再次超越了所有基线。使用两个LLM骨干的消融研究表明，移除并行候选生成或轨迹数据库访问都会降低最终平均分数。这些结果表明，仿真轨迹可以指导复杂基于仿真的调度中的针对性代码级策略改进。

## Abstract
Simulation-based optimization (SBO) evaluates executable policies under stochastic dynamics, but most methods treat the simulator as a black box: aggregate scores rank candidates without revealing why they fail or which policy logic should change. We present an LLM-guided heuristic design framework that uses repeated simulation for selection and event-level traces for diagnosis. Each incumbent is assessed through multiple replications, while replaying its lowest-scoring one produces a queryable trace. A manager agent formulates bottleneck hypotheses from this evidence, and editing agents implement parallel code-level revisions. After execution checks and repeated evaluation, best-so-far selection retains only improvements. LLM revision occurs between evaluation batches, while a fixed policy controls each simulation run.   We evaluate the framework in a discrete-event simulation of dynamic production and automated guided vehicle (AGV) scheduling. Across five independent optimization runs with Gemini-3.1-Pro, final mean scores averaged 77.51 on the simulator's 0-100 scale. In the highest-scoring run, trace-based diagnoses motivated proactive charging, distance-aware AGV assignment, and rebalanced dispatch priorities, raising the best-so-far mean score from 62.49 to 78.61. On 100 matched seeds, the best final policy outscored representative rolling-MILP, rule-based, and metaheuristic policies on every seed and retained its advantage under random faults without re-optimization. After separate re-optimization for a longer horizon and variable order interarrival times, the resulting policies again outscored all baselines. Ablations with two LLM backbones showed that removing either parallel candidate generation or trace-database access reduced final mean scores. These results show that simulation traces can guide targeted code-level policy improvement in complex simulation-based scheduling.

# 基于模拟轨迹的LLM引导启发式设计：动态生产与AGV调度案例研究

## 1. 核心问题与研究动机

- **背景**：仿真优化（SBO）是在随机环境下评估可执行策略的主流方法，但大多数现有方法将仿真器视为**黑箱**——仅使用聚合分数对候选方案进行排序，却无法揭示策略失败背后的运行机制，也无法指明策略代码中哪些条件、优先级或阈值需要修改。
- **问题**：
  - 数学规划虽将决策问题显式表达，但需要简化假设以保证可解性；
  - 传统 SBO 方法（元启发式、导数-free）只依赖标量 KPI 反馈，缺乏对候选生成的可操作指导；
  - 现有 LLM 启发式设计方法（EoH、FunSearch、ReEvo）虽用自动化评估选择候选，但仍未将**事件级仿真轨迹**作为候选生成的输入。
- **核心思想**：仿真器能够记录时间戳化的状态转移、资源状态、队列、延迟等事件级轨迹（simulation traces），这些轨迹提供了聚合分数所不具备的诊断证据，可以连接"结果"与"运行机制"，从而指导更有针对性的策略修订。

## 2. 方法论

- **框架总览**：提出 LLM 引导的启发式设计框架，将仿真优化拆解为**选择（selection）**与**诊断（diagnosis）**两个互补环节：
  - **选择**：使用 R 次独立随机重复的**平均分**评估候选策略，确定是否取代当前最优（incumbent）。
  - **诊断**：重放当前策略得分最低的随机复制，生成可查询的**事件级轨迹**（queryable trace），为策略修订提供证据。
- **核心公式**：
  - 优化目标：\( \pi^* \in \arg\max_{\pi \in \Pi} J(\pi), \quad J(\pi) := \mathbb{E}_\xi[S(\pi; \xi)] \)
  - 样本均值：\( \bar{S}_R(\pi) = \frac{1}{R} \sum_{r=1}^{R} S_r(\pi) \)
  - 完整评估过程：`Evaluate_R(π) = (S̄_R(π), τ(π))`，即平均分 + 诊断轨迹。
- **诊断重放机制**：选取 \( r(\pi) \in \arg\min_{1 \le r \le R} S_r(\pi) \) 作为最低分复制；因给定策略与随机输入时仿真具备确定性，重放精确复现该复制的事件历史。重放分数不参与平均分计算，仅用于诊断。
- **多智能体循环（Algorithm 1）**：
  1. **Manager Agent**：基于当前策略、平均分、诊断轨迹（含分组KPI汇总和从轨迹数据库查询的记录/摘要）以及历史搜索信息，提出瓶颈假设和多个（k_t≈3–4个）互不相同的修订方向。
  2. **Editing Agents**：每个编辑体在隔离工作区内实现一个修订方向，生成可执行候选策略代码。
  3. **验证与评估**：候选须通过执行检查，失败时允许有限次修复尝试（N_repair=3）。通过检查后执行 R=10 次评分复制 + 1 次诊断重放。
  4. **选择与保留**：best-so-far 选择，仅在候选平均分严格高于当前策略的存储平均分时晋升；否则保留 incumbent 及其评估输出。
- **策略表示**：每个策略由可执行代码组成，包含产线选择规则、运输任务排序规则、AGV 分配规则、充电控制规则，以及可选的参数估计逻辑；产品路由与局部工作站排序由仿真器控制。
- **终止条件**：最大迭代数 T=10、目标分数 S_tar=80、无改进耐心 C_stall=3 次迭代。

- **RQ3（鲁棒性）**：
  - 3000 分钟时域：框架平均分 **74.16**，优于 GA（63.06）等所有基线；
  - 可变订单到达 U(5,15)：框架 **76.34**，优于所有基线；
  - 随机故障下无重新优化：优化策略仍保持对全部基线的优势（中位差 14.02–14.57 分）。
- **消融结论**：
  - 去掉并行候选生成：平均分下降（Gemini-3.1-Pro 从 77.51 → 73.65；GPT-5.4-mini 从 72.84 → 66.22），且稳定性显著恶化（最小值降至 62.36/62.29），平均运行迭代数减少，易早停；

## 7. 方法优点

- **超越黑箱**：用事件级轨迹替代纯标量反馈，使 LLM 能基于"为什么失败"而非"结果多差"来修订策略，显著提高修订的针对性。
- **代码级策略空间**：LLM 可新增、删除、重构策略逻辑，突破固定维度向量、规则组合或编码调度的限制，例如引入主动充电、距离感知分配等基线的决策空间不存在的行为。
- **批次间修订 / 批内固定策略**：LLM 仅在评估批次之间介入，仿真运行由固定策略控制，保证策略可检查、可版本化、可复现测试，避免运行时 LLM 推理延迟带来的不确定性。
- **多智能体并行**：Manager–Editors 的角色分离让一个瓶颈假设对应多个独立修订方向并行生成，降低单一无产出方向的浪费，同时保持了代码执行的隔离性。
- **工程完备性**：候选策略执行失败时具备有限修复尝试（repair attempts），通过执行检查评估门槛，减少无效候选影响搜索。
- **实验设计规范**：匹配种子重评估、独立种子集评估、统计检验、多次独立运行区间报告、消融分析一应俱全，证据链扎实。
- **框架通用性**：不要求任何目标函数分解，适用于可代码化决策策略 + 可重复仿真 + 可查询轨迹 + 自动执行检查的离散事件系统（如制造、仓储、港口、医院物流）。

## 8. 不足与局限

- **未使用结构化优化历史**：框架保留了之前的策略、反馈与评估结果，但仅作为上下文记录提供，没有将成功/失败的修订转化为结构化记忆（如"哪些修改有效/无效"）供未来复用。论文明确承认这一点。
- **单一 incumbuent 中心搜索**：best-so-far 机制只保留一条策略分支，不保留多个有潜力的备选分支，搜索多样性有限（尤其当改进放缓时），实际效果是对并行候选的容错性依赖较高。
- **随机评估依赖有限样本**：平均分基于 R=10 的有限复制估计，晋升决策使用独立种子集，虽被匹配种子重评估部分缓解，但存在有限样本选择的偏差风险。
- **最低分轨迹的选择偏差**：选择最低分复制作为诊断对象，故意聚焦于失败模式，可能不代表典型运行条件；论文未隔离不同轨迹选择策略（如最高分、中位数、聚合轨迹）的影响。
- **消融实验的耦合性**："无数据库"配置同时移除轨迹数据库访问和数据驱动参数估计，二者对效果的贡献未分离。
- **应用范围有限**：实证仅覆盖一个动态生产 + AGV 调度案例；应用边界要求仿真器已验证、可校准、输出可靠，实际操作中此条件并不总是满足。
- **性能差距来源未完全归因**：最优策略与基线性能差距的一部分来自更大的决策空间（如充电控制），而非纯粹的轨迹引导优势；尽管消融部分弥补，但在基线空间中加入充电控制后再做对比会更公平。
- **算力成本未量化**：论文未报告 LLM API 调用总量、推理成本或总体仿真 CPU 开销，对实际部署的经济可行性讨论不充分。
