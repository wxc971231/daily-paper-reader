## 摘要
生成结构有效的合成表格数据仍然困难：具有高统计保真度和下游实用性的输出仍可能违反具有语义意义的领域约束。我们研究了三种互补的列间约束族——方程、线性不等式和逻辑依赖——的发现与执行。我们统一的基于工具的工作流将这三类约束表示为机器可执行的假设，并应用通用接口进行全表验证、确定性诊断和反例引导修订。一个与生成器无关的后处理器协调对未修改的表格生成器输出进行特定于约束族的修复。在精心设计的行为审计和端到端评估中，完整工作流比一次性直接提示改进了留出集上的违规检测，而后处理在所有保留的适用约束上产生零测量违规，提高了大多数数据集的下游效用，并在很大程度上保留了单变量边缘分布。

## Abstract
Generating structurally valid synthetic tabular data remains difficult: outputs with high statistical fidelity and downstream utility can still violate semantically meaningful domain constraints. We study the discovery and enforcement of three complementary inter-column constraint families---equations, linear inequalities, and logical dependencies. Our unified tool-grounded workflow represents all three as machine-executable hypotheses and applies a common interface for full-table validation, deterministic diagnosis, and counterexample-guided revision. A generator-agnostic postprocessor coordinates family-specific repairs on outputs from unchanged tabular generators. Across curated behavioral audits and end-to-end evaluations, the complete workflow improves held-out violation detection over one-shot direct prompting, while postprocessing yields zero measured violations for every retained, applicable constraint, improves downstream utility on most datasets, and largely preserves univariate marginals.

## 1. 核心问题与整体含义

合成表格数据（synthetic tabular data）被广泛用于模型开发、系统测试和数据分析，但当真实数据稀缺或难以使用时，仅仅追求统计保真度和下游效用的生成模型仍可能产出**结构上不合理、违反领域约束**的记录，例如：

- 订单的配送时间早于下单时间；
- 订单小计（subtotal）与单价 × 数量不一致；
- 配送方式与产品类型不兼容。

这类违规不仅会损害模拟与决策支持，还可能扭曲下游模型，并让合成数据通过简单的逻辑检查即可与真实数据区分。作者指出，以往工作存在两大耦合难题：

1. **异构语义关系的可执行化**：方程、线性不等式、逻辑依赖等不同约束族，需要统一表示为可被机器执行、可在完整参考表上验证和修订的假设；
2. **跨共享列的协调修复**：对未修改的生成器输出进行后处理时，一次修复可能使另一约束失效，或对生成分布造成不必要扭曲，因此需要协调的修复策略而非独立修正。

论文的整体目标，是构建一个**端到端框架**，将 LLM 智能体引入“约束发现—验证—修订—后处理执行”的全流程，从而在不改动生成器模型的前提下，使合成数据满足可验证的列间语义约束。

## 2. 方法论

### 2.1 核心思想

- 将三类互补的列间约束统一为**机器可执行假设（executable hypotheses）**，共享同一套“全表验证—确定性诊断—反例引导修订”的接口。
- 使用 **LLM 智能体**提出候选约束，由**确定性工具**（而非 LLM 自身）做验证，从而保证可复现性与可靠性。
- 设计一个**生成器无关的后处理器（postprocessor）**，以协调方式修复合成表中的违规，无需访问生成器内部或重新训练。

### 2.2 约束族与表示方式

| 约束族 | 语义 | 可执行表示 |
|---|---|---|
| 方程（Equational） | 数值列间的确定性算术恒等关系，如 `subtotal = unit_price × quantity` | 生成 Python `check(df)` 函数，逐行评估并返回布尔 Series |
| 线性不等式（Linear Inequality） | 数值列上的可行半空间，如 `delivery_time ≥ order_time` | JSON DSL：参与列、系数映射、比较符号（≤/≥）、右端常数 |
| 逻辑依赖（Logical Dependency） | 类别列的条件可接受性，如 `zipcode → state`、部分规则 | JSON DSL：determinant 列、dependent 列、值表（value table），支持多可取值与部分配置 |

### 2.3 约束发现流程（LLM-Guided Discovery）

1. **数据集画像（Profiling）**：为每列构建语义描述、数据类型、数值统计（范围、分位数、均值、标准差、众数）或类别统计（高频值及频率）。
2. **候选生成（Hypothesis Generation）**：LLM 智能体接收数据集描述、列画像、无放回采样的 `n_ctx = 100` 行上下文，输出结构化假设（含 id、描述、参与列、可执行表示）。
3. **全表验证（Tool-Grounded Validation）**：族特定验证器在完整参考表上计算违规率：

   \[
   VR(h)=\frac{|V_h|}{|A_h|}
   \]

   仅当 \(VR(h) \le \tau_{vio}=0.005\) 时保留。对逻辑依赖，还要求经验支持度：

   \[
   Supp(h)=\frac{|A_h|}{N} \ge \tau_{sup}=0.005
   \]

4. **反例引导修订（Counterexample-Guided Revision）**：验证失败时返回聚合诊断与最多 `n_cex = 20` 条违规行作为反例，要求 LLM 修订，最多 `R_rev = 3` 轮。
5. **多轮发现（Multi-round Discovery）**：进行 `R_disc = 3` 轮，后续轮次告知已接受/拒绝的假设，鼓励探索新关系。
6. **合并去冗余（Consolidation）**：族特定地移除重复、子sumed、冗余假设；对线性不等式按规范化系数向量去重并保留最小右端；对 LD 保证依赖图无环、值表原子化。

### 2.4 约束执行（Generator-Agnostic Enforcement）

按“逻辑依赖 → 方程 → 线性不等式”的顺序修复：

- **逻辑依赖修复**：固定 determinant 列，从该条目允许的依赖值集合中（优先参考条件分布）采样替换 dependent 值；对重叠规则求可接受集合并集，按拓扑顺序处理。
- **方程修复**：LLM 生成 `fix(df)` 修复函数，并经验证保留；使用 **KS-补引导启发式**（KS-complement-guided heuristic）联合选择修复目标列与执行顺序：
  - 先最大化最差单一修复的边际变化 \(\tau^\star = \max_{P\in\mathcal{P}}\min_{(c,j)\in P}\Delta_{c,j}\)；
  - 再在最优阈值下选择总预测变化最大的完整调度；
  - 修复后冻结所有参与列，防止后续修复使其失效。
- **线性不等式修复**：将每行联合投影到共同可行区域，固定方程参与列与零方差列：

  \[
  \min_{z\in\mathbb{R}^{|S_{num}|}} \sum_{j\in U}\left(\frac{z_j-\tilde{x}_{ij}}{s_j}\right)^2
  \quad \text{s.t. } Az \le b,\; z_j=\tilde{x}_{ij}\ \forall j\in P
  \]

  整数列采用连续松弛；投影阶段不保证整性。

## 3. 实验设计

- **LLM 骨干**：GPT-5.6 Luna 与 Claude Sonnet 5。

- **协议**：每次独立 70/30 划分训练生成器一次、采样 3 张合成表；每张表用本文工作流独立发现约束并后处理，共 252 组配对（raw vs. postprocessed）评估。
- **指标**：

  - 线性可行性距离 LFD（越低越好，0 为完美）；
  - 下游效用 TSTR（Train on Synthetic, Test on Real）；

## 6. 主要结论与发现

1. **发现效果显著提升**：完整验证-修订工作流在全部 18 个 family–backbone–metric 比较中优于一次性直接提示。逻辑依赖任务提升最大（GPT-5.6 下精确率/召回率从 0.442 升至 0.974）；线性不等式在 Claude-5 下准确率从 0.815 升至 0.959；方程基线已接近上限，本文仍达到近 1.000。
2. **后处理实现“零违规”**：在后处理后的所有保留适用约束下，CVR、sCVC、LFD 均为 0，方程一致性 R² 精确达到 1；说明修复没有把一种违规“转移”成另一种。
3. **效用与边际保真基本保持**：TSTR 效用在 STEEL 上 0.486 → 0.976，在 4/7 数据集上提升，其余最多下降 0.042；Column Shapes 变化仅 −0.009 至 +0.019。
4. **原始生成器存在不同失败画像**：TabDDPM 的 LD 违规最低（3.1%）但 LFD 最高（2.23）；TVAE 的 LFD 最低；CTGAN 方程最弱（R² = −0.97）；Gaussian Copula 的 LD 违规最高（36.4%）。**仅选生成器不足以保证结构有效性**。
5. **修复顺序至关重要**：E→L 在 NBA 全部 36 个设置中达到双族零违规；反序 L→E 则在 24 个设置（66.7%）中重新引入线性违规，说明投影必须放在最后。
6. **KS 引导调度优于随机可行调度**：在约束满足平等的条件下，平均 Column Shapes 提升 0.025（4 个数据集提升 0.020–0.053，NEWS 持平）。

## 7. 优点

- **统一可执行接口**：将异构约束族统一为可验证、可诊断、可修订的机器可执行对象，设计简洁

- **LLM 与确定性工具解耦**：由 LLM 扮演“假设提出者”而非“验证者”，所有候选约束均经全表验证与反例驱动修订，既充分利用了 LLM 对复杂语义的抽象能力，又避免了幻觉与不可复现的推理，工程上更可靠。
- **生成器无关且无需重新训练**：约束发现与后处理完全独立于 CTGAN、TVAE、TabDDPM 等具体生成器，下游用户可直接对已生成的表格进行“修复”，显著降低落地成本。
- **协调式修复而非孤立修复**：通过冻结参与列、KS-补引导调度、跨族优先级设计，有效避免了“修复 A 破坏 B”的连锁失效问题，实验也证明了顺序的重要性。
- **评估体系完整且可复现**：覆盖 3 个约束族、7 个数据集、4 种生成器范式、252 组配对评估，并消融了关键组件（发现轮数、上下文数、修复顺序、调度策略），结论充分支撑核心主张。

## 8. 不足与局限

尽管整体设计严谨，本文在方法论和实验上仍有一些值得注意的局限：

- **假设候选质量受限于 LLM 的“视野”**：发现流程依赖 LLM 从 100 行上下文与画像中生成候选假设。若某个关键约束在样本中极少出现（甚至完全不出现），LLM 可能不会提出；反例引导修订也只能修正已提出的假设，无法凭空产生新的关系。因此，该方法更适合约束存在**可观察痕迹**的场景。
- **阈值设定可能造成边界误差**：验证阶段采用单一的 \(\tau_{vio}=0.005\) 和 \(\tau_{sup}=0.005\)。对于稀疏但真实存在的业务规则（如仅有 0.3% 的事务包含特定组合），可能会被错误地当作“噪声”拒绝；反之，噪声也可能被当作有效约束接受。实验未提供对这些阈值的敏感性分析。
- **方程修复依赖 LLM 生成“修复函数”**：虽然修复函数需通过验证才被保留，但 LLM 可能生成在验证数据上完全有效、却隐含错误逻辑（如简单整体平移）的修复方案，从而扭曲原始数据分布。论文只报告了边际保真度，未深入检测二阶或多变量相关性畸变。
- **线性不等式投影对整数列采用连续松弛**：投影后的连续值需通过舍入恢复为整数，这可能导致轻微违反不等式约束（如舍入后 \(x>y\) 变成了 \(x \le y\)）。论文在主实验中报告 LFD=0，推测是评估时使用了与投影相同的容忍条件，或舍入后恰好仍满足约束，但并未明确讨论该问题。
- **计算开销披露不完整**：论文只给出了生成器训练与采样的约 18 小时，未统计 LLM 提示（profile、假设生成、修订）与后处理修复的额外时间和 API 成本。考虑到发现流程包含多轮、多候选，实际端到端成本可能远高于传统数据生成。
- **逻辑依赖不支持概率规则**：现实中大量列间关系并非绝对确定（例如“绝大多数订单配送方式与地区有关”），但本文只接受违规率低于 0.5% 的硬规则。对弱依赖、软约束没有建模能力，限制了在噪声较大业务数据上的适用性。
- **发现评估的“提示”问题**：审计任务中每行被改写一格的构造方式，可能让 LLM 通过“单格异常”而非真正的语义关系识别违规，特别是在线性不等式任务中；虽然这符合“可检测异常”的目标，但可能高估了模型对完整语义的掌握。

## 9. 总结与启示

本文提出了一套以 LLM 智能体为“约束发现器”、以确定性工具为“验证器”和“执行器”的端到端框架，成功地将合成数据的列间语义约束问题拆分为“发现”与“满足”两个可独立优化的子问题。核心贡献在于：其一，将方程、线性不等式、逻辑依赖三类异构规则统一为可执行且支持反例修订的表示；其二，设计了生成器无关、协调式后处理流水线，避免修复过程中的级联失效；其三，通过大规模实验证明，该工作流在不牺牲下游效用与边际分布的前提下，能将合成数据的约束违规率降至零。

这项工作给合成数据领域带来三点启示：**第一，生成准确性不应只看单列分布**，列间结构性约束是合成数据能否被实务系统接受的关键门槛；**第二，LLM 并非一切问题的万能解**，将生成式模型与确定性验证工具结合，能获得二者各自无法单独实现的可信度；**第三，后处理修复需要系统性协调**，简单的逐列修补往往在解决一个约束的同时破坏另一个约束，只有在全表语境下规划修复顺序与冻结策略，才能达到真正的“零违规”。

未来的可能方向包括：引入软约束与概率依赖建模、支持跨表外键一致性、自适应选择验证阈值，以及将约束发现扩展为主动采样查询而非被动从上下文中推断。
