## 摘要
让语言模型可靠地解决约束问题，通常意味着让它们将问题翻译成形式化规范，并将搜索委托给可靠的求解器。但翻译本身就是一个语言模型任务，不忠实的翻译会使求解器忠实地解决错误的问题。现有的流水线只修复崩溃的翻译，返回求解器的错误消息，并在程序运行但出错时保持沉默。我们用证明取代错误消息：当生成的程序不可满足时，我们从模型自身的约束中提取一个最小不可满足核，并返回恰好无法同时成立的那组约束，这是一个无泄漏的信号，可定位故障。在一个包含77个问题且具有精确预言机的新基准测试中，翻译为回答集编程在七个领域中的六个上是忠实的，仅在聚合覆盖调度上失败，这使翻译代价集中在一个可诊断的模式中。最小核而非简单的错误，才是阻止较弱模型为不可行问题捏造解决方案的关键，将捏造率从79%降至7%。与此同时，一个强链式思维基线在准确性上与符号路线相当，因此该路线的价值不在于准确性，而在于证书及其拒绝捏造的能力。

## Abstract
Making language models solve constraint problems reliably often means having them translate the problem into a formal specification and delegating the search to a sound solver. But the translation is itself a language-model task, and an unfaithful translation makes the solver faithfully solve the wrong problem. Existing pipelines repair only translations that crash, returning the solver's error message and falling silent when the program runs but is wrong. We replace the error message with a proof: when the generated program is unsatisfiable, we extract a minimal unsatisfiable core over the model's own constraints and hand it back the exact set that cannot hold together, a leakage-free signal that localizes the fault. On a new benchmark of 77 problems with an exact oracle, translation to Answer Set Programming is faithful on six of seven domains and fails only on aggregate coverage scheduling, which concentrates the translation tax in one diagnosable pattern. A minimal core, rather than a bare error, is what stops a weaker model from fabricating solutions to infeasible problems, cutting fabrication from 79% to 7%. A strong chain-of-thought baseline meanwhile matches the symbolic route on accuracy, so the route's value is not accuracy but certificates and its refusal to fabricate.

### 1. 核心问题与整体含义

- **研究动机**：语言模型（LLM）在求解调度、排座、分配、装箱等离散约束问题时，自回归解码无法保证全局组合约束的满足性，因此主流方案是"翻译+求解"架构——由LLM将自然语言问题翻译为形式化规范，交给可靠的符号求解器（如clingo/ASP）执行搜索。该方案的瓶颈在于**翻译的忠实性**：LLM翻译可能产生两类错误——
  - 语法错误（求解器报错，显式可见）；
  - **静默错误**（程序能运行但约束不忠实：多加了约束导致可解问题误报不可满足，或少写了约束导致非法解被接受）。现有流水线（如Logic-LM）只处理第一种情况，对运行但错误的翻译**保持沉默**，导致模型可能为不可行问题捏造解决方案。
- **核心问题**：如何在不泄漏真实答案的前提下，为模型提供"证明式"反馈，使其能区分"翻译有误"与"问题本身不可行"。
- **整体含义**：错误反馈应升级为**证明式信号**——求解器的证明产物（最小不可满足核）可作为一等公民反馈给LLM；符号路线的价值不在准确率，而在于**可验证的证书**与**拒绝捏造的可靠性**。

### 2. 方法论

#### 2.1 总体框架：四阶段循环
1. **翻译**：LLM生成结构化ASP编码（JSON格式，包含facts、rules、optimize三部分）；
2. **求解**：调用clingo执行搜索；
3. **分类**：将求解结果分为四类——`OK`（有答案集）、`SYNTAX ERROR`（语法/接地错误）、`EMPTY`（可满足但无assign原子）、`UNSAT`（程序良构但不可满足）；
4. **修复与迭代**：根据分类构建不同类型的诊断反馈，返回LLM修订编码，迭代最多K=3次。

#### 2.2 核心设计：决策契约 assign/2
- 所有决策统一用单一关系 `assign(Var, Value)` 表达，由一个choice rule约束每个变量恰好绑定一个值；
- 一切需求以**完整性约束**（`:-` 开头规则）形式表达；
- 该契约带来三个好处：统一打分标准、编码规模稳定（决策逻辑规则数恒定，仅facts随问题扩展）、**将容易出错的完整性约束与固定的facts/choice rule分离**——这正是核提取所依赖的划分。

#### 2.3 最小不可满足核的提取（Algorithm 1：删除过滤）
- 设基础程序B（facts+choice rule）本身可满足，不一致必来自模型生成的完整性约束集合C；
- 通过**删除过滤**（deletion-based filtering，QuickXplain族最简单成员）计算最小不可满足子集 C⋆：依次尝试删除每个约束，若剩余仍然不可满足则保留删除；
- 需要至多 |C| 次SAT检查，在基准规模下代价可忽略；
- 两个关键性质：
  - **结构化**：C⋆ 是"这些约束无法共存"的证明，明确指出需复审的约束；
  - **无泄漏**：所有检查只运行在模型自产程序上，不接触ground truth/预言机/参考编码——模型获得的是其自身翻译的不一致定位，而非正确答案，评估不受污染。

#### 2.4 类型化修复提示
- `UNSAT`：列出C⋆中约束原文，明确"要么修正其中一个约束，要么保留不变以报告不可行"——使"问题不可行"成为合法答案；
- `SYNTAX ERROR`：携带grounder消息要求修复解析；
- `EMPTY`：要求补充choice rule以产出 assign/2 原子。

#### 2.5 对照设置：隔离核心信号
- 构建与TYPED+CORE完全一致但反馈不同（仅返回裸求解器错误消息）的 `GENERIC` 设置，复现Logic-LM式错误消息自我修正；
- 因两设置仅反馈信息内容不同，行为差异可归因于核心信号本身。

- 每个实例含自然语言描述 + assign/2 结构化规范，描述包含所有约束（无信息隐藏惩罚）；
- 使用**确定性编码器**（独立于LLM）计算真实可行性和最优值；**独立预言机**对任意赋值打分（约束满足、可行性、目标值）；
- 实例带5类标签：`feasible` / `tight`（数值紧但可解）/ `infeasible`（正确行为是报告不可满足）/ `stress`（更大）/ `xl`（60–120个决策变量，仅测可行性）。

### 6. 主要结论与发现

1. **直接prompt不可靠，CoT很强**：Direct只达74.0%可行性准确率，并为14个不可行实例中的3个（21.4%）捏造了方案；而CoT达98.7%且零捏造。
2. **翻译税集中在一个领域**：六域中无修复管线已达100%可行性准确率（着色域甚至超过CoT：100% vs 94.7%）；全部差距来自**排班调度域**（需要聚合覆盖与工人上限的计数约束），无修复管线段为0%。
3. **修复是单调的**：核修复将主模型从84.4%提至89.6%，77个实例中4个首次失败被修复、**零个被改坏**；失败耗尽迭代预算的恰是模型无法编码的调度实例。
4. **核心在弱模型上起关键作用**：deepseek-v3.2上，泛化错误消息修复导致79%的不可行实例被捏造方案（模型删掉真实约束直到求解器返回模型）；核修复将捏造率降至7%（Fisher精确检验显著）。
5. **符号路线的价值不在准确率而在证书**：管线从不在不可行问题上捏造方案（0% vs Direct 21.4%），返回的解在优化实例上可证明最优（零最优性差距）；这是prompting难以提供的单次保证。
6. **规模层面无统一优势**：CoT在stress层保持约100%，仅xl层降至90%；管线的跨层优势依赖个别实例，且自身在120变量的调度实例上失败。

### 7. 优点

- **信号本身的设计极具洞察**：用最小不可满足核作为反馈，是"求解器证明产物"作为LLM修复信号的首创性工作；核具备结构性与无泄漏性双重保证，从原理上杜绝了评估污染；
- **统一决策契约 assign/2** 使七个异质领域在同一格式下可比，编码规模恒定、预言机统一、核心提取分离清晰；同时保证所有基线（包括prompting）获同等信息量；
- **干净的消融对照**：GENERIC与TYPED+CORE仅反馈信息含量不同，使因果归因可信；
- **诊断粒度精细**：将失败精确定位到一个形式化模式（聚合覆盖计数），而非笼统归咎于模型或领域，为"按模式信任"提供了依据；
- **明确区分了"修复发生"与"修复所携带的信息"**，实证揭示了反馈形状对弱模型行为的决定性影响；
- 发布基准和预言机，可复现性好。

### 8. 不足与局限

- **模型覆盖面窄**：核心优于裸错误的效应仅在deepseek-v3.2上显著；gemma4:31b上两信号无法区分——"反馈形状重要"的结论尚不适合推广为通用规律，需要更多模型验证；
- **实验规模有限**：基准仅77个实例，xl层仅10个，准确率交叉点（如90节点图）依赖单一实例，统计功效不足；
- **方法适用范围受限**：ASP难以快速证明大规模数值优化问题或大规模不可满足性，限制了向更大实例扩展；统一的 assign/2 契约不适合含派生数值量的问题；
- **无法捕捉"缺失约束"**：若模型漏写了某个约束，程序可能可满足但无效——这种错误只能被评估预言机事后捕获，无法在循环内修复；作者认为引入验证器是自然下一步；
- **计算成本不对称**：符号管线每问题多次调用LLM（vs prompting一次或两次），准确率持平以额外推理开销为代价，论文未量化此"计算溢价"；
- **单配置下的领域结论**：调度域失败是在固定prompt下报告的，改换prompt或提供计数示例可能缩小差距，作者承认应视为配置属性而非自动形式化的规律；
- **不可行性报告 vs 求解器能力边界**：在xl层以可行性only形式规避了大规模不可满足/最优性证书问题，限制了"证书价值"论证的规模范围。

## 总结

该论文以"最小不可满足核指导修复"重构了神经符号约束求解的反馈回路：将反馈从"求解器说不行"升级为"求解器证明哪几个约束不可能同时成立"，在77个问题、7个领域、2个模型上实证了该方法在弱模型上大幅降低可行性捏造（79%→7%），同时清醒地重新校准了符号离载路线与强CoT基线的价值定位——**前者提供可验证证书，后者仅在聚合准确率上与之持平**。研究设计严谨、信号设计巧妙，为LLM形式化修复开辟了"证明级反馈"这一有价值的方向；但模型与规模覆盖面有限，且缺失约束检测尚未入循环，仍需后续工作拓广。
