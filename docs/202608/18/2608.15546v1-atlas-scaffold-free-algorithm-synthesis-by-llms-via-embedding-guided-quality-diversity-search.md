## 摘要
大多数基于LLM的自动化算法设计方法在人工指定的脚手架内优化特定组件，固定整体组织和组件交互。我们提出ATLAS，一个用于组合优化中免脚手架全算法合成的嵌入引导的质量-多样性框架。问题规范提供目标和约束；最小I/O接口仅固定实例和解决方案格式；LLM选择并重构组件、交互及控制流。这种自由度扩大了搜索空间，带来无效候选和过早收敛到单一设计区域的风险。ATLAS独立检测执行、接口和可行性失败，重新计算目标，并应用基于错误条件的修复；基于相似性的存档管理跨嵌入空间区域保留算法以对抗过早收敛。其三层搜索精炼最佳设计，为其他区域提供专门的精炼机会，并执行跨区域合成以重组组件及其交互。在四个NP难问题上，ATLAS优于几种最先进的组件合成方法和一种匹配的全合成基线，同时与强人工设计算法保持竞争力。一次ATLAS运行保留来自不同嵌入空间区域的多个性能相当的算法，而非单一设计。代码检查发现，这些多组件设计在主要构造或全局搜索主干上有所不同。我们的结果表明，嵌入引导的质量-多样性搜索可以使扩大的全算法设计空间实际可搜索。源代码和精确可执行提示词可在<https://github.com/Danial-Yazdani/ATLAS>获取。

## Abstract
Most LLM-based automated algorithm design methods optimize a designated component within a human-specified scaffold, fixing overall organization and component interactions. We present ATLAS, an embedding-guided quality-diversity framework for scaffold-free full-algorithm synthesis in combinatorial optimization. The problem specification supplies objectives and constraints; a minimal I/O interface fixes only instance and solution formats; the LLM chooses and restructures components, interactions, and control flow. This freedom enlarges the search space, risking invalid candidates and premature convergence to one design region. ATLAS independently detects execution, interface, and feasibility failures, recomputes objectives, and applies error-conditioned repair; similarity-based archive management preserves algorithms across embedding-space regions to counter premature convergence. Its three-layer search refines the best design, gives other regions dedicated refinement opportunities, and performs cross-region synthesis to recombine components and their interactions. Across four NP-hard problems, ATLAS outperforms several state-of-the-art component-synthesis methods and a matched full-synthesis baseline while remaining competitive with strong human-designed algorithms. One ATLAS run retains several algorithms with comparable performance from distinct embedding-space regions rather than a single design. Code inspection finds that these multi-component designs differ in their primary construction or global-search backbone. Our results suggest that embedding-guided quality-diversity search can make the enlarged full-algorithm design space practically searchable. Source code and exact executable prompts are available at <https://github.com/Danial-Yazdani/ATLAS>.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景约束**：现有的大多数 LLM 自动算法设计方法（如 FunSearch、EoH、ReEvo 等）都是“组件合成”——LLM 只生成一个在人工指定脚手架（scaffold）中担任固定角色的启发式组件（如优先选择函数、构造规则），而算法的整体组织结构、组件交互和控制流由人类预先固定。这种设计限制了 LLM 的创新空间，使其难以发现超出预设架构的全新算法。
- **核心问题**：如何让 LLM 在“无脚手架”（scaffold-free）条件下直接合成**完整的可执行优化算法**？这相当于将搜索空间从“组件空间”扩大为“完整算法空间”，但空间扩大后带来两个挑战：
  1. 无效候选增多（执行错误、接口不符、约束违反、解不可行等）；
  2. 算法设计空间可能是多模态的，传统适应度驱动的搜索容易过早收敛到少数设计区域。
- **论文含义**：作者提出 **ATLAS**（Archive-based Three-Layer Algorithm Synthesis），用“嵌入引导的质量-多样性搜索”来驾驭这个更大的设计空间，使完整算法合成不仅可行，而且能与人工设计的强算法竞争。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想
- **免脚手架全算法合成**：只给 LLM 提供问题规格（目标、约束、解的有效性要求）和一个最小 I/O 接口（入口函数、实例输入格式、解输出格式），不规定任何内部组件清单、功能划分或控制流。LLM 必须自己完成解的构造、约束处理、内部状态管理和停止逻辑，并输出可直接执行的 Python 程序。
- **嵌入引导的质量-多样性（QD）存档**：
  - 每个算法表示为三元组：名称、描述、源代码。
  - 用预训练嵌入模型 `mGTE-large-en-v1.5` 对三者拼接后的文本进行编码，以余弦距离作为算法间语义相似度。
  - 基于该距离进行检索、聚类、去重和剪枝，从而在嵌入空间中保留覆盖多个“算法区域”的多样化候选集合，避免过早收敛。
- **错误条件修复（Repair）**：外部评估器独立检查执行、接口、资源、可行性等失败；失败候选经分类诊断后再由 LLM 用针对性提示重新生成并完整重评估。评估采用“全有或全无”有效性规则——任一实例失败即拒绝候选。
- **三层搜索策略**：
  - **Layer 1（精英区域精炼）**：重点细化当前最佳算法及其 k 近邻；
  - **Layer 2（分布式区域精炼）**：给非精英聚类代表独立的细化机会；
  - **Layer 3（跨区域合成）**：通过 Combine/Diverge 算子在不同聚类代表之间进行重组和发散，生成混合算法或新设计。

### 2.2 关键技术细节
- **语义算子**：零参考 `Create`，单参考 `Improve / Tune / Simplify`，多参考 `Combine / Diverge`，外加 `Repair`。所有算子都以提示词实现，接收完整源代码作为上下文。
- **存档管理**：
  - 两级去重：严格阈值（相似度>0.95）无条件去重；软阈值（相似度>0.90）且训练目标差异小于容忍度 ϵ 时才去重；
  - 容量裁剪（上限 Nmax=100）：优先移除嵌入空间中最相似且性能较差的一对中的弱者，同时保护当前精英区域 G*，避免破坏局部精炼能力。
- **初始化**：两阶段：先用 `Create` 生成 20 个初始算法，再用 `Diverge` 从当前存档中采样参考生成 30 个远离已有区域的新算法，以获得更广的嵌入空间覆盖。
- **聚类**：用 k-medoids（FasterPAM）+ 自动选择 K（Silhouette），K∈[3, ⌊√|A|⌋]，聚类用于生成操作区域。
- **算法流程（高层）**：初始化 → 评估/修复/嵌入/加入存档 → 去重/剪枝 → 聚类并形成精英区和非精英区 → 按三层策略调度算子 → 候选评估入档 → 循环直到预算耗尽 → 输出训练最优算法、最终存档与各聚类代表。

## 3. 实验设计

### 3.1 基准问题
四个 NP-hard 组合优化问题：
- **FSS**（置换流水车间调度，n50/m10）；
- **CVRP**（带容量约束车辆路径问题，n50）；
- **CVRPTW**（带时间窗的 CVRP，n50）；
- **QAP**（二次分配问题，n50）。

### 3.2 数据与协议
- 每个问题 31 个训练实例（种子 2024）+ 31 个独立测试实例（种子 42）；
- 训练集只用于搜索和存档构建，测试集仅在选定算法后评估一次；
- LLM 方法运行 R=5 次独立合成，每次产出一个训练最优算法并测试；
- 统计检验：对每个测试实例将 5 次运行的原始目标均值化，用 Wilcoxon 符号秩检验（显著性水平 0.05）进行两两比较。

### 3.3 对比方法
- **人类设计领域算法**：FSS 用 NEH、IG-TB、Iterative Beam Search；CVRP/CVRPTW 用 PyVRP、OR-Tools、VROOM；QAP 用 Robust Tabu Search、Simulated Annealing、BLS、BMA。

## 6. 主要结论与发现

- **主结果**：在四个默认基准上，ATLAS 在统计上显著优于所有 LLM 基线（EoH、ReEvo、MCTS-AHD、EOH-FULL）。
- 相对参照人类方法（统计最佳人工方法）的平均差距很小：
  - FSS：0.347%；
  - CVRP：0.094%（与 PyVRP 无显著差异）；
  - CVRPTW：0.000%（显示精度下持平）；
  - QAP：0.460%。
- **扩展规模**：ATLAS 在四个额外规模设置中均为最佳 LLM 方法；FSS n25/m5 与 IG-TB 无显著差异，CVRP n25 持平最好人工均值。
- **多模态保留**：单次运行最终存档中，多个来自不同嵌入区域的代表算法测试差距均在 1% 以内；代码检查显示它们具有不同的核心构造或全局搜索机制（如 regret insertion、savings、cluster、ruin-and-recreate、遗传、禁忌、LNS 等），并出现组件复用和混合。
- **消融结论**：
  - 完整三层配置最佳；
  - 语义引导优于适应度引导和随机引导；
  - 双阶段初始化显著提升嵌入空间覆盖；
  - GPT-5-MINI + Low 推理是性价比最优设置；
  - 更强的底层 LLM 会略提高 ATLAS 性能，但差距不大。

## 7. 优点

- **方法创新性强**：从“组件合成”跃迁到“无脚手架全算法合成”，研究问题具有前沿性和通用意义。
- **搜索架构设计合理**：嵌入引导的 QD 存档 + 三层资源分配，兼顾精炼、多样化和跨区域重组，可解释性强。
- **评估体系严谨**：独立验证解、全有或全无有效性、错误分类修复、训练/测试隔离、配对统计检验、运行时和内存限制等，工程细节完善。
- **消融系统、透明度高**：对嵌入、初始化、搜索引导、层配置、推理成本、底层 LLM 均做受控研究，还给出了完整提示词和开源代码，可复现性强。
- **结果有说服力**：与强人工方法差距在 0.5% 以内，且保留多种竞争算法，体现了 QD 搜索的实际价值。

## 8. 不足与局限

- **LLM 依赖与成本**：依赖单一 LLM（GPT-5-MINI）和 API，合成一次需 10–15 小时；底层 LLM 更换会影响性能，但未测试开源/本地方案。
- **公平性偏差**：与人工 C++ 基线比较时存在实现语言差异；同为墙钟上限，Python 合成的算法在等效操作数上吃亏。
- **样本量小**：每个方法仅 5 次合成运行，统计功效有限；测试实例规模小且为合成分布，泛化到真实大规模实例的证据不足。
