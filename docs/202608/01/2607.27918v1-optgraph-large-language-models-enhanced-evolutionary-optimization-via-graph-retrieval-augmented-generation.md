## 摘要
大型语言模型（LLMs）已成为自动化进化优化的强大工具，但现有方法在模式复用、错误感知细化以及跨多样化任务的检索鲁棒性方面仍存在局限。为解决这些局限，我们提出了OptGraph，这是首个引入图检索增强生成（GraphRAG）的优化智能体工作流。具体而言，OptGraph首先将可复用经验构建为类型化图，捕捉建模模式、问题形式化、实现细节和错误修正之间的关系。在推理阶段，OptGraph利用图邻域信息丰富检索到的知识，提供结构化上下文以改进建模、验证和迭代细化。此外，OptGraph支持自适应知识更新，能够将执行轨迹和验证反馈提炼为可复用的图知识，而无需进行LLM参数微调。在基准数据集上的大量实验表明，我们提出的OptGraph相较于最先进的基于提示的自动优化框架，平均精确准确率提高了8.9%。我们的代码已在https://github.com/xianchaoxiu/OptGraph上公开。

## Abstract
Large language models (LLMs) have emerged as a powerful tool for automated evolutionary optimization, but existing methods remain limited in pattern reuse, error-aware refinement, and retrieval robustness across diverse tasks. To address these limitations, we propose OptGraph, the first optimization agentic workflow that introduces graph retrieval-augmented generation (GraphRAG). Specifically, OptGraph first constructs reusable experience as a typed graph, capturing the relationships among modeling patterns, problem formalization, implementation details, and error corrections. In the inference stage, OptGraph leverages graph neighborhood information to enrich retrieved knowledge, providing structured context to improve modeling, verification, and iterative refinement. Moreover, OptGraph supports adaptive knowledge updates, enabling the distillation of execution traces and verification feedback into reusable graph knowledge without ndertaking LLM parameter tuning. Extensive experiments on benchmark datasets show that our proposed OptGraph achieves an average exact accuracy 8.9% higher than the state-of-the-art prompt-based automated optimization frameworks. Our code has been made available at https://github.com/xianchaoxiu/OptGraph.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与算法流程

**核心思想**：将可复用优化知识构建为异构图，在推理时检索图邻域结构而不是孤立文本，通过验证机制和错误感知修复实现迭代细化，并基于执行轨迹和验证反馈动态更新图结构。

**关键技术细节**：

- **Step 1：GraphRAG 构建**
  - 从优化基准、求解器轨迹、人类专家经验、领域文献中收集数据。
  - 通过错误挖掘、结构解析、模板提取、模式蒸馏，将原始资源转化为图知识。
  - 构建有向异构图：`G = (V, E, τ, ρ)`
  - 节点类型包括：`Problem Type, Variant, Description, Math Model, Code Snippet, Typical Error, Fix Hint`
  - 初始包含 15 个种子模式，后续增长到 48 个。

- **Step 2：知识建模**
  - 对输入问题 P，计算与每个 Variant 节点的相关性得分 `S(P, v)`。
  - 选出 top-k 变体节点：`Rk(P) = TopK S(P, v)`
  - 扩展邻域：`K(P) = ∪ ({v} ∪ N(v))`，得到关联的 Problem Type、Description、Math Model、Code Snippet、Typical Error、Fix Hint。
  - 三个子任务：
    - 问题识别：判断问题类型和变体。
    - 模型公式化：`M̂ = A_model(P, K(P))`
    - 程序合成：`Ĉ = A_code(P, M̂, K(P))`

- **Step 3：验证机制**
  - 执行代码：`(o, ŷ, s) = Exec(Ĉ)`，得到输出、数值答案、执行状态。
  - 三维一致性检查：目标验证（objective verification）、约束验证（constraint verification）、程序验证（program verification）。
  - 验证结果：`z = V(P, M̂, Ĉ, o, ŷ, s) ∈ {0,1}`
  - 失败时检索错误相关上下文（Typical Error 和 Fix Hint 节点），调用修复代理：
    `(M̂(t+1), Ĉ(t+1)) = A_repair(P, η(t), K_err(P))`
  - 记录执行轨迹 `ξ = {(η(t), z(t), f(t))}τ_{t=0}`。
  - 最大修复轮数 T = 3。

- **Step 4：GraphRAG 更新**
  - 分析执行轨迹，提取候选图更新：`ΔG_q = U(ξ_q) = (ΔV_q, ΔE_q)`。
  - 节点插入或合并：`G(q) = G(q−1) ⊕ ΔG_q`，避免冗余增长。
  - 不修改 LLM 参数，只更新外部图知识，实现跨任务非参数知识积累。

**算法流程**（Algorithm 1）：
1. 初始化图 G(0)。
2. 对每个问题 q：检索 top-k 变体节点 → 扩展邻域 → 问题识别 → 初始建模与代码生成。
3. 执行并根据验证结果循环修复，最多 T 轮，若通过则输出答案；否则记录失败轨迹。
4. 对轨迹进行经验提取和图更新。
5. 返回最终答案、轨迹和更新后的图 G(Q)。
