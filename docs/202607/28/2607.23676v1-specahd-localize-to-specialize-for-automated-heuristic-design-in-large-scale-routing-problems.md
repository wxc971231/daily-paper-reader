## 摘要
基于大语言模型的自动化启发式设计通常对整个实例或在固定求解器组件内对可执行程序进行评分。在大规模路由问题中，局部重构缩小了每个优化任务的规模，但同一当前解中的修复区域可能表现出截然不同的结构。因此，单一构造规则必须在这两者之间进行妥协。本文提出了SpecAHD，一种用于实例内专门化的耦合双层框架。上层搜索学习在何处暴露有界修复区域，而下层搜索则为诱导出的修复任务演化出一组互补的可执行启发式程序。上层程序决定了下层所见的修复任务，而检查后的修复结果决定了上层程序的评估。下层目标倾向于平均表现良好或能解决当前程序库处理不善的任务的启发式程序。对于由固定上层程序和固定下层候选池诱导出的修复任务，该目标是单调子模的，允许以(1-1/e)近似保证进行贪婪程序库选择。在四个路由问题和多个大语言模型骨干上，SpecAHD相比于最强的竞争性AHD基线，将保留的客观成本降低了高达57.7%，并在大多数公共实例上优于每个实例的基线包络。

## Abstract
LLM-based automated heuristic design (AHD) typically scores executable programs on complete instances or within fixed solver components. In large-scale routing problems, localized reconstruction reduces the size of each optimization task, but repair regions within the same incumbent can exhibit substantially different structures. One construction rule must therefore compromise across them. In this paper, we propose SpecAHD, a coupled bilevel framework for within-instance specialization. An upper-level search learns where to expose bounded repair regions, while a lower-level search evolves a complementary repertoire of executable heuristics for the induced repair tasks. The upper-level program determines the repair tasks seen by the lower level, while checked repair outcomes determine how upper-level programs are evaluated. The lower-level objective favors heuristics that perform well on average or solve tasks that the current repertoire handles poorly. For the repair tasks induced by a fixed upper-level program and a fixed lower-level candidate pool, this objective is monotone submodular, allowing greedy repertoire selection with a (1-1/e) approximation guarantee. Across four routing problems and multiple LLM backbones, SpecAHD reduces held-out objective cost by up to 57.7% against the strongest competing AHD baseline and outperforms the per-instance baseline envelope on most public instances.

### **论文核心总结**

#### 1. 核心问题与整体含义

-   **研究动机**：大规模路由问题（如车辆路径规划VRP、旅行商问题TSP）的求解常通过“破坏-修复（ruin-and-recreate）”策略，即“大型邻域搜索”（LNS）。现有基于大语言模型（LLM）的自动化启发式设计（AHD）方法，通常使用一个单一、全局的构造规则来修复所有被暴露的局部结构。
-   **核心问题**：同一解中的不同局部修复区域（如客户集群、时间窗口约束、路线交叉点）可能具有截然不同的结构。一个单一、固定的修复规则必须对所有区域进行折中，导致整体性能受限。此外，选择修复区域和设计修复规则这两个任务是相互依赖的，难以独立优化。
-   **整体含义**：本文的核心思想是将“专门化”从“实例层面”推进到“实例内部”。即，不仅要为不同问题寻找不同的启发式，还要为**同一个问题解中的不同局部结构**寻找和匹配最合适的专用修复规则。

#### 2. 方法论

-   **核心思想**：提出**SpecAHD**，一个**耦合的双层（Bilevel）搜索框架**，将“区域暴露”和“启发式设计”联合优化。
    -   **上层搜索**：学习一个“区域暴露程序”，决定当前可行解的**哪一部分**在实例的哪一轮迭代中被暴露出来以进行修复。
    -   **下层搜索**：演化出一套**互补的、可执行的启发式程序库**，库中的每个程序都是针对特定类型修复任务的“专家”。
    -   **耦合机制**：上层程序决定了下层程序将面对的修复任务；检查后的修复结果（是否可行、改进多大）反过来决定上层程序的优劣。

-   **关键技术细节**：
    1.  **双层修复接口**：
        -   **上层程序**`g`：产生一个原始区域序列，经过一个**问题特定的验证器**`V`，输出至多`K`个**有效且互不相交的修复区域**`z`。
        -   **下层程序**`h`：是一个可执行的构造性启发式。在给定的局部修复状态`r`下，逐步骤选择下一个动作（如下一个客户、下一段路径）。
        -   **检查机制**：任何修复操作后，都会使用**精确的检查器**`F`验证**整个解**的可行性。如果修复失败或导致不可行解，则**回滚**到修复前的状态，保证解的可行性。
    2.  **下层目标函数与子模性**：
        -   目标是选择一个不超过`q`个启发式程序组成的集合`H`，最大化目标函数`Jg(H)`。该函数包含两项：平均质量和任务覆盖率。
        -   对于**固定的上层程序、固定的任务集和固定的候选池**，目标函数`Jg`是**单调子模（Monotone Submodular）函数**。这使得可以使用**贪婪选择算法**，并保证最终选择的程序集性能不低于最优解的**63.2%**（(1-1/e)近似比）。
        -   互补性来自于第二项：只有当一个新程序能在某些特定任务上超越现有程序集中**所有**程序的最高得分时，它才会被纳入。
    3.  **修复响应归档与路由**：
        -   所有检查过的(区域、局部结构描述符、启发式程序、检查得分)记录存储在**修复响应档案**`A`中。
        -   在推理时，对于新的修复区域，算法会计算其局部结构描述符，并在档案中查找最相似的`k`个历史任务，根据已有得分**加权平均**地预测每个启发式程序的表现，从而选择最佳的“专家”进行修复。
    4.  **交替搜索**：
        -   由于完全解耦上层和下层搜索代价高昂，SpecAHD采用**有限预算下的交替**方式。在一个回合内，固定当前上层程序，完全运行下层搜索来更新程序库和档案；然后，固定下层程序库和档案，运行上层搜索来更新区域暴露程序。

1.  **收敛性不保证**：论文明确指出，子模性保证仅适用于**固定上层程序**和**固定候选池**内的贪婪选择，并不适用于整体的**交替双层搜索**的收敛性或全局最优性。
