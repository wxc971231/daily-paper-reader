## 摘要
大语言模型（LLMs）已成为自动化演化优化的强大工具，但现有方法在模式复用、错误感知修正以及跨不同任务的检索鲁棒性方面仍存在局限。为解决这些局限，我们提出OptGraph，这是首个引入图检索增强生成（GraphRAG）的优化智能体工作流。具体而言，OptGraph首先将可复用经验构建为带类型图，捕捉建模模式、问题形式化、实现细节和错误修正之间的关系。在推理阶段，OptGraph利用图邻域信息丰富检索知识，提供结构化上下文以改进建模、验证和迭代精化。此外，OptGraph支持自适应知识更新，能够将执行轨迹和验证反馈蒸馏为可复用图知识，而无需进行LLM参数微调。在基准数据集上的大量实验表明，我们提出的OptGraph相比最先进的基于提示的自动化优化框架，平均精确准确率提高了8.9%。我们的代码已发布于https://github.com/xianchaoxiu/OptGraph。

## Abstract
Large language models (LLMs) have emerged as a powerful tool for automated evolutionary optimization, but existing methods remain limited in pattern reuse, error-aware refinement, and retrieval robustness across diverse tasks. To address these limitations, we propose OptGraph, the first optimization agentic workflow that introduces graph retrieval-augmented generation (GraphRAG). Specifically, OptGraph first constructs reusable experience as a typed graph, capturing the relationships among modeling patterns, problem formalization, implementation details, and error corrections. In the inference stage, OptGraph leverages graph neighborhood information to enrich retrieved knowledge, providing structured context to improve modeling, verification, and iterative refinement. Moreover, OptGraph supports adaptive knowledge updates, enabling the distillation of execution traces and verification feedback into reusable graph knowledge without ndertaking LLM parameter tuning. Extensive experiments on benchmark datasets show that our proposed OptGraph achieves an average exact accuracy 8.9% higher than the state-of-the-art prompt-based automated optimization frameworks. Our code has been made available at https://github.com/xianchaoxiu/OptGraph.

## 2. 论文提出的方法论

### 2.1 核心思想

OptGraph 首次将 GraphRAG 引入优化智能体工作流，将优化知识组织为**带类型的异构有向图**，在推理时通过图邻域扩展检索结构化上下文，并通过执行验证与反馈驱动的自适应图更新实现无需参数微调的知识积累。

### 2.2 关键技术细节

#### ① GraphRAG 构建

- 从优化基准、求解器轨迹、人类专家经验、领域文献中收集原始知识；
- 通过**错误挖掘、结构解析、模板提取、模式蒸馏**将资源转化为图结构，表示为有向异构图：

```
G = (V, E, τ, ρ)
```

- 节点类型包括：`Problem Type`（问题类型）、`Variant`（变体）、`Description`（描述）、`Math Model`（数学模型）、`Code Snippet`（代码片段）、`Typical Error`（典型错误）、`Fix Hint`（修复提示）。
- 初始图包含 15 个种子模式，更新后可扩展至 48 个模式（见后文）。

#### ② 知识建模

给定自然语言优化问题 `P`：

1. 计算问题与每个 `Variant` 节点的语义相关性得分 `S(P, v)`；
2. 通过 Top-K 选取最相关的变体节点：

```
R_k(P) = TopK_{v∈V_var} S(P, v)
```

3. 扩展所选节点的图邻域：

```
K(P) = ∪_{v∈R_k(P)} ({v} ∪ N(v))
```

得到包含问题类型、描述、数学模型、代码片段、典型错误与修复提示的结构化上下文。

- **问题识别**：根据检索上下文判断问题类型与变体；
- **模型公式化**：`\hat{M} = A_model(P, K(P))`，生成数学模型；
- **程序合成**：`\hat{C} = A_code(P, \hat{M}, K(P))`，生成可执行代码。

#### ③ 验证机制

- 执行生成的代码，获得原始输出 `o`、提取数值答案 `ŷ` 与执行状态 `s`；
- 在三个维度进行一致性检查：**目标验证**、**约束验证**、**程序验证**；
- 验证结果 `z ∈ {0,1}`，失败时检索错误感知上下文（典型错误与修复提示），通过修复代理更新公式与代码；
- 验证-修复循环最大迭代 3 次。

#### ④ GraphRAG 更新

- 记录执行轨迹 `ξ`（公式、程序、输出、答案、状态、验证反馈）；
- 从轨迹中提取候选更新 `ΔG_q = U(ξ_q)`，包括新节点与边；
- 更新图 `G^(q) = G^(q−1) ⊕ ΔG_q`：先插入无可比先例的知识，再合并语义与功能相似的节点，控制图冗余增长。

### 2.3 算法流程

整体流程如 Algorithm 1 所示：初始化图 `G(0)` → 对每个问题执行检索 → 建模 → 生成代码 → 执行验证 → 失败则修复（最多 3 轮）→ 记录执行轨迹 → 更新图结构 → 处理全部问题后返回最终图 `G(Q)` 与各问题答案。

## 6. 论文的主要结论与发现

1. **OptGraph 在全部 6 个数据集上取得最优精度**：平均精确准确率 75.4%（比最优提示型方法高 8.9%），平均 5% 容忍准确率 83.2%。
2. **结构化图知识优于孤立文本检索**：朴素 RAG 在 IndustryOR、MAMO-C、OptMATH 上降低了原框架精度，而 GraphRAG 显著提升精度，说明建模知识需要保留结构关系。
3. **验证机制是主动修复机制，而非简单过滤器**：验证触发后修复在多个数据集上取得高成功率，尤其复杂数据集收益明显。
4. **GraphRAG 可作为通用模块**：集成至 CoE、OptiMUS、Lean-LLM-OPT 后均一致性地提升了性能。
5. **3 轮验证为最佳平衡点**：超过 3 轮后过度修复带来性能下降。
6. **非参数知识积累可行**：无需微调 LLM 参数即可从执行轨迹中积累可复用经验。
