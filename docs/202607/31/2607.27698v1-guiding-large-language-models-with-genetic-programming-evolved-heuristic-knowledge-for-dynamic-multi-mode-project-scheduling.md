## 摘要
在动态多模式项目调度中，活动具有可选的执行模式和不确定的持续时间，同时优先关系和有限资源约束着它们的执行。启发式优先规则支持快速的在线决策，但其设计需要大量的领域专业知识。遗传规划（GP）超启发式方法可以自动演化此类规则。与此同时，大型语言模型（LLM）为解释调度信息和说明决策提供了灵活的接口。然而，零样本LLM决策可能缺乏领域知识、消耗大量令牌，并且在重复查询中结果有所变化。因此，GP演化规则为引导LLM决策提供了潜在的调度知识来源。与现有使用LLM支持启发式演化的LLM-GP混合方法不同，我们反向转移知识，利用从高质量GP规则中提取的知识来引导在线LLM决策者。我们从高质量GP规则中提取知识，并通过特征选择、特征提示、规则参考和规则遵循来注入这些知识。这些机制在调度性能、令牌消耗、决策稳定性以及生成理由中体现的特征焦点方面进行了评估。GP衍生的指导总体上改善了未引导的LLM，但其表示形式至关重要。简化决策上下文或提供明确的决策逻辑比突出重要特征更有效。特征选择在令牌效率上最优，而规则遵循在更高的令牌成本下实现了强性能。指导还提高了决策稳定性，并改变了生成理由中所表达的特征。

## Abstract
In dynamic multi-mode project scheduling, activities have alternative execution modes and uncertain durations, while precedence relations and limited resources constrain their execution. Heuristic priority rules support fast online decisions, but their design requires substantial domain expertise. Genetic programming (GP) hyper-heuristics can automatically evolve such rules. Large language models (LLMs), meanwhile, provide a flexible interface for interpreting scheduling information and explaining decisions. However, zero-shot LLM decisions may lack domain knowledge, consume many tokens, and vary across repeated queries. GP-evolved rules therefore provide a potential source of scheduling knowledge for guiding LLM decisions. Unlike existing LLM--GP hybrids that use LLMs to support heuristic evolution, we transfer knowledge in the reverse direction, using knowledge extracted from high-quality GP rules to guide an online LLM decision maker. We extract knowledge from high-quality GP rules and inject it through Feature Selection, Feature Hint, Rule Reference, and Rule Follow. These mechanisms are evaluated in terms of scheduling performance, token consumption, decision stability, and the feature focus expressed in generated rationales. GP-derived guidance generally improves the unguided LLM, but its representation matters. Simplifying the decision context or supplying explicit decision logic is more effective than highlighting important features. Feature Selection offers the best token efficiency, whereas Rule Follow achieves strong performance at greater token cost. Guidance also improves decision stability and changes the features expressed in generated rationales.

- **GP超启发式的价值**：遗传规划（GP）可从训练实例中自动演化调度规则，生成的规则以数学表达式的形式组合调度特征，可应用于未见过的实例。
- **LLM的短板**：零样本大语言模型虽然能理解调度上下文并生成解释，但其天然缺乏可靠的调度领域知识与数值规则执行能力，导致决策质量不稳定、token 消耗大，且重复查询时结果多变。

## 2. 方法论

### 2.1 整体框架

- 框架分为**离线启发式知识提取**与**在线LLM调度决策**两个阶段。
- 在线阶段，动态调度环境在每个决策点构建一个满足前置约束与资源约束的“候选活动-模式集合”Ct，将当前项目状态、特征定义表和候选信息表提供给LLM；LLM从中选择一个候选，返回结构化结果给环境执行；随后更新项目状态，进入下一个决策点，直至项目全部活动完成。

### 2.2 知识提取流程

- 对每个前置约束场景分别进行30次GP训练；
- 不仅保留每轮最终最优个体，还保留**每一代的代际最优个体**——因为训练过程中使用了随机种子轮换机制，不同代数个体在多种模拟条件下得到，可能对应不同的调度行为；
- 所有汇总规则在单独的验证集上评估，记录**调度效果（makespan）**与**规则规模（复杂度）**两个指标；
- 基于效果与复杂度的权衡，选取领先的非支配前沿规则构建**基于Pareto的精英规则库**。

### 2.3 五种LLM变体与四种引导机制

| 变体 | 特征集 | 特征提示 | GP规则 | 引导类型 |
|---|---|---|---|---|
| Basic | 全部 | 无 | 无 | 无引导基线 |
| Feature Selection（特征选择） | 仅选定特征 | 无 | 无 | 信息限制 |
| Feature Hint（特征提示） | 全部 | 有 | 无 | 注意力引导 |
| Rule Reference（规则参考） | 全部 | 无 | 有（咨询性） | 软性规则引导 |
| Rule Follow（规则遵循） | 全部 | 无 | 有（规定性） | 硬性规则引导 |

- **特征级知识提取**：从精英规则库中统计各特征出现频率，按频率排序后保留**累计占比达80%**的最频繁特征作为选定特征集。
  - **Feature Selection**：只向LLM提供选定特征的定义和候选特征值，减少决策上下文中的干扰信息；
  - **Feature Hint**：提供全部特征，但在提示中明确标注哪些是GP认为的重要特征。
- **规则级知识提取**：从精英规则库中选择一条**紧凑的高质量GP规则**（规则规模小，便于LLM解释与计算）。
  - **Rule Reference**：将GP规则提供为“建议性”参考，LLM可结合其他信息灵活偏离；
  - **Rule Follow**：将GP规则作为“规定性”指令，要求LLM严格按该规则计算优先级并选择最优候选。

## 6. 主要结论与发现

- **RQ1（性能）**：
  - **Feature Selection、Rule Reference、Rule Follow 总体上显著优于Basic**；Feature Hint效果不稳定（有4次显著变差的情况）；

- **RQ2（效率与稳定性）**：
  - token消耗随前置约束减弱而增加（候选集变大）；
  - **思考token占比最大**，输出token很少；

- **总体评价**：本文提出了一个完整且可复现的“GP 演化知识 → LLM 在线决策”框架，研究问题清晰，实验设计在多个维度上具有开创性。结果有力地证明：即使不使用微调，仅通过知识提取和提示工程，也能将符号演化的调度启发式注入纯零样本 LLM，并取得稳定、可解释的性能提升。这一路径为 LLM 在组合优化调度领域的应用提供了新的知识接口范式，也为“神经符号结合”的研究提供了一个低成本的落地方案。
- **未来研究方向**：
  - 验证知识引导在**跨项目拓扑迁移**上的表现，以及在更大规模和真实项目数据上的适应性；
  - 探索**动态选择规则库**：根据当前项目状态自动选择最合适的 GP 规则作为引导，代替固定单规则；
  - 将**自然语言翻译层**加入 GP 规则的提示中，使 LLM 对复杂表达式形成正确的语义理解，降低计算错误率；
  - 比较多种 LLM 与多轮对话场景下的引导效果，研究**上下文遗忘**与早期错误传播问题；
  - 引入**强化学习或在线反馈**，使引导知识能够在 LLM 与环境的交互中持续更新，而非离线静态。
