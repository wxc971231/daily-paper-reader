## 摘要
组合优化的启发式设计仍然严重依赖专家知识，而现有的大语言模型（LLM）增强进化方法通常进化孤立的算法组件，即使其中一个组件决定了另一个组件操作的搜索状态。本文提出LLM驱动的启发式组件联合生成（LLM-HCJG），这是一个基于种群的框架，在共享设计蓝图下联合生成并共同进化相互依赖的启发式组件。应用于引导式局部搜索（GLS）时，LLM-HCJG将解决方案初始化与惩罚构建耦合，并将生成的对嵌入增强的在线搜索机制中。所得形式进一步从旅行商问题（TSP）迁移到容量受限车辆路径问题（CVRP）。理论分析建立了两个组件之间不可分离的状态转移效应以及生成一致性方面的优势。在合成实例和41个公共TSPLIB/CVRPLIB基准上，LLM-HCJG持续获得低最优性差距，包括在29个TSPLIB实例中的28个和全部12个CVRPLIB实例上取得最佳或并列最佳结果。消融和结构分析进一步表明，这些收益与跨组件兼容性和一致性相关，而非孤立组件重组。这些结果支持在有限样本、适度成本训练下，所评估的路径设置中的有效跨实例迁移。

## Abstract
Heuristic design for combinatorial optimization remains heavily reliant on expert knowledge, while existing large language model (LLM)-enhanced evolutionary methods typically evolve isolated algorithmic components, even when one determines the search state on which another operates. This paper proposes LLM-driven Heuristic Components Joint Generation (LLM-HCJG), a population-based framework that jointly generates and co-evolves interdependent heuristic components under a shared design blueprint. Applied to guided local search (GLS), LLM-HCJG couples solution initialization with penalty construction and embeds the generated pair into an enhanced online search mechanism. The resulting form is further transferred from the traveling salesman problem (TSP) to the capacitated vehicle routing problem (CVRP). Theoretical analysis establishes the non-separable state-transition effects between the two components and the advantage in generation consistency. Across synthetic instances and 41 public TSPLIB/CVRPLIB benchmarks, LLM-HCJG attains consistently low optimality gaps, including best or tied-best results on 28 of 29 TSPLIB instances and all 12 CVRPLIB instances. Ablation and structural analyses further indicate that these gains are associated with cross-component compatibility and alignment rather than isolated-component recombination. These results support effective cross-instance transfer within the evaluated routing settings under limited-sample, modest-cost training.

## 2. 论文提出的方法论

**总体框架**
- 算法级个体表示：个体为 \(a_j = (Z_j, F_j^s, F_j^u)\)，其中：
  - \(Z_j\)：一句话表述的共享设计蓝图（shared blueprint），约束两个组件的联合设计原则；
  - \(F_j^s\)：解初始化函数（代码元组：Thought + Code）；
  - \(F_j^u\)：惩罚构造函数（代码元组：Thought + Code）。
- 两者以“有序对”形式生成、评估、选择和进化，因为 \(F_j^s\) 决定了 \(F_j^u\) 作用的起始搜索状态支撑（边集合），而 \(F_j^u\) 决定该状态如何被扰动。

**LLM 驱动的进化循环**
- 初始化：LLM 在同一个 task description 中配对生成两个函数，并输出共享蓝图。
- 交叉（概率 \(\sigma_1=1.0\)）：选择 l=2 个父代，e1 提示强调“完全不同”、e2 强调“可受启发但不同形式”，生成 s=1 个子代，子代蓝图或继承/改写父代蓝图，再据此条件生成两个组件。
- 变异（概率 \(\sigma_2=0.5\)）：三类 m1/m2/m3 提示分别做性能提升型、参数重调型、结构精简型修改。
- 父本选择：基于排序的轮盘赌，适应度越高采样概率越大（公式(7)）。
- 种群管理：父代+后代按适应度截断保持恒定种群大小。

**理论分析与形式化设计**
- 将引导距离更新一般化为：
  \[
  U_{f^u}(D,S,P) = D + A(S)\odot B_{f^u}(D,P)
  \]
- **定理3.1（不可分离性）**：若存在初始化组件差异导致某边状态不同、且惩罚构造差异导致该边调整强度不同，则二者的联合效用存在非零混合差分 \(I\neq0\)；因此不存在只在单一组件层面的加法分解 \(G^s(f^s)+G^u(f^u)\)。这从理论上论证了**组件对是进化的基本单元**。
- **定理3.2（共享蓝图一致性）**：
  - 在同一共享蓝图条件下生成的组件对必然落入一致性集合 \(C=\{(f^s,f^u):\zeta^s(f^s)=\zeta^u(f^u)\}\)；
  - 若独立随机抽蓝图，则一致性概率为 \(\sum_z \pi_\theta(z|x)^2\)，必然存在正的失配概率。
- 在经典 GLS 之上加入四个固定在线机制（非 LLM 进化目标）：(i) 选择 top-5 正惩罚差分的“有影响力边”；(ii) 围绕边端点执行 2-opt/relocate/swap 定向扰动；(iii) 扰动后按原始距离做局部改进；(iv) 每 50 次外层迭代恢复到当前最优解，避免搜索漂移。

**GLS 从 TSP 到 CVRP 的扩展**
- 经典 GLS 只处理单一环路的 TSP；CVRP 需同时做客户分配、路由排序、容量可行性等。
- 作者沿用“边惩罚+局部改进”的引导搜索原则，定义三个保可行性邻域：route内 2-opt、route间 relocate、route间 swap；将 LLM_HCJG 生成的组件嵌入这一转移后的搜索流程。

## 3. 实验设计

**训练设置**
- 训练实例：TSP/CVRP 各 100 节点，在单位正方形 [0,1]² 均匀采样；CVRP 额外固定 depot=(0.5,0.5)，客户需求整数 [1,9]，车辆容量 50，约 10–11 辆车；使用 LKH 生成参考解。
- 每个候选适应度在 K=5 个训练实例上评估（从 64 个实例池中抽取），即“limited-sample”训练。
- 种群 N=10，进化代数 \(N_g=10\)；采用 GPT-4o-mini 作为通用 LLM。

**测试集**
- 合成实例：
  - TSP：规模 \(n\in\{20,50,100\}\)，每个规模 1000 个实例；
  - CVRP：容量 50，规模 n∈{20,50,100}，每个规模 64 个实例。
- 公开基准：
  - **TSPLIB**（29 个实例，规模约 51–200），沿用 EoH 原论文的选择；
  - **CVRPLIB**（12 个实例，覆盖 A/B/E/P/M/X 系列，规模 32–190，稀疏/密集车队、容量紧/松等情况）。
- 各方法限制：TSP 终止于 100 秒或 1000 次外层迭代；CVRP 终止于 20 秒或 1000 次外层迭代。

**比较基线**
- 传统手调启发式：LS、GLS、KGLS（r/c 变体）、EBGLS；
- 神经网络类：AM、POMO、LEHD、GNNGLS、NeuralGLS；
- 之前 LLM-EC 方法：EoH 与 ReEvo；
- 此外设置 **FA-GLS**（在经典 GLS 基础上只加 LLM-HCJG 的在线搜索机制，但保留贪心初始化和经典惩罚规则），用于区分框架层提升与 LLM 设计组件带来的提升。
- 实验协议：三次独立完整进化运行选出三个精英，在公开验证集上选最佳一个，再用它做 10 次重复测试并报告均值——与 ReEvo 最终精英选择流程一致。

**消融与结构分析**
- 交叉组合消融：EoH–EoH、EoH–HCJG、HCJG–EoH、HCJG–HCJG（即“初始化组件–惩罚组件”的来源组合），只改变组件来源，其他框架设定相同。
- 后验结构指标：Focus（惩罚信号是否集中在当前状态边上）与 Diversity（惩罚强度在边之间是否差异化）；对最优个体报告 (Focus, Diversity)。
- 统计检验：对 gap 配对差异做 20,000 次百分位 bootstrap 95% CI，并用双侧 Wilcoxon 符号秩检验。

## 6. 论文的主要结论与发现

1. **联合进化是核心增益来源**：共享蓝图下配对生成的组件结构兼容性高，跨组件消融（HCJG–HCJG < EoH–HCJG/HCJG–EoH < EoH–EoH）显示性能差异来自*成对组件间的协同*，而非把独立设计的模块简单重组。
2. **理论可解释**：定理3.1、3.2分别从搜索状态转移不可加性（不可分离性）和条件失配概率消除/降低（生成一致性）上支撑“配对作为进化单元”的正确性。
3. **在更强搜索框架下依然有效**：FA-GLS 较原始 GLS 大幅改进后，LLM-HCJG 在这之上进一步把 TSP100 gap 从 0.140% 降到 0.070%，CVRP100 gap 从 4.523% 降到 3.526%。
4. **跨实例/跨问题迁移能力强**：
   - TSPLIB 平均 gap 0.017%，28/29 实例达到最佳或并列最佳（最好的一对一竞争者 ReEvo 为 0.030% 与 23/29）；
   - CVRPLIB 平均 gap 1.686%，全部 12/12 实例最佳/并列最佳（EoH 为 3.601%，ReEvo 为 9.451%）。
5. **训练效率高**：仅用 5 个训练实例做适应度评估加上 10 代、10 个个体的种群，即可获得可迁移的强启发式，训练耗时远低于 EoH/ReEvo 的同类流程。
6. **对约束强的多路线问题更突出**：从 E-n76-k10、P-n55-k15 的 route 图看，LLM-HCJG 的路网更紧凑、避免跨区连接与长距折返；其优势不仅来自更强扰动，更来自“应往哪些边施加惩罚”的准确定位以及初始划分与惩罚结构的对齐。

## 7. 优点

- **问题辨识精准**：指明现有“LLM-for-AHD”在耦合组件维度上的缺失，不只是加入 reflection 或调参。
- **表示设计有新意**：三层结构（组件函数层/个体组合层/进化提示层）+ 共享设计蓝图，将“算法级个体”从“单规则代码”提升为“耦合组件对+设计原则”，可读、可验证。
- **理论与实证互证**：两个定理分别给出不可分离性和一致性优势；消融统计结果与理论预测相互印证。
- **对“框架提升 vs 生成组件提升”做了干净隔离**：通过 FA-GLS 对照，说明 LLM 生成组件在增强框架之上仍能带来增益，论证清晰。
- **保留可解释性**：自动化进化后仍能给出数学化解释（如 TSP 的距离+随机最邻惩罚、CVRP 的容量感知距离塑形），便于分析内化机制。
- **成本意识强**：以很小的 LLM 查询预算达到 SOTA 水平，便于复现和推广。
- **统计严谨性较好**：提供 bootstrap CI 与 Wilcoxon 检验，而非仅报告平均 gap。

## 8. 不足与局限

- **实验分布较窄**：合成与训练均采用均匀随机的坐标点、固定容量50、整数需求；未验证聚簇分布、非对称距离、超大规模（>200节点）或其他容量分布下是否依然有效。
- **仅两个路由问题**：TSP 和 CVRP 虽然结构不同，但都属于同一“边惩罚–局部搜索”流派；对作业车间调度、车辆调度、选址等“组件耦关联更强”的问题尚未演示。
- **可比较基线受限**：CVRP 上缺少 KGLS/EBGLS/神经方法；部分结果沿用原文、部分重新进化，跨论文/跨版本的公平一致性有残余风险。
- **LLM 查询层面的深入剖析不足**：论文报告了候选有效率和总查询数，但未具体给出 token 消耗量、API 费用或对 prompt 模板的敏感性分析。
- **训练-测试同分布风险**：训练也是 100 节点均匀随机、容量50，而公开基准主要是 50–200 节点的地理实例；虽然证明可迁移到 TSPLIB/CVRPLIB 的“实例尺寸迁移”，但对更大规模（如 1000+节点）或真实路网拓扑的 transfer 并未提供证据。
- **随机种子处理着墨不够**：三次进化运行用于选精英，但未系统报告不同种子下的方差；仅说选了最佳验证精英后做 10 次运行。
- **“阶段最优”风险**：结果是最终 elite（best-validated）的性能，而非“平均发生（平均运行）”性能，真实部署时一次运行无法保证找到这种 elite。
- **在线机制本身固定**：top-5 边、50 次重启、邻域窗口等属于人工设定，未通过 LLM 或参数敏感性分析验证是全局最优选择；因此框架仍隐含先验设计。
- **缺少公开代码/可复现验证**：作者计划在见刊时公开，评审过程中无法核验代码细节、prompt 完整组装与随机数行为。
